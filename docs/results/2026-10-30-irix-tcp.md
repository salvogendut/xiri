# Initial IRIX TCP client path — 2026-10-30

Toolchest now creates TCP sockets, sets its socket options and reaches real
connection refusal on NetBSD, using unmodified IRIX libraries. The new
implementation also transfers data between original o32/n32 test programs
and a native NetBSD peer. This is a bounded client transport checkpoint;
it does not establish a working IRIX desktop.

Against a live native Xvfb server, Toolchest successfully connects and then
calls `getsockname` (IRIX trap 1094). That unsupported call returns ENOSYS
(89); Toolchest closes its socket and exits 1 with a display-open error. The
native client controls still work. This is a later and distinct boundary
from the original unsupported socket call; no X protocol handshake or
Toolchest window is qualified.

## Implementation and pins

NetBSD branch `xiri/irix-tcp`, revision
[`512fe461da7`](https://github.com/salvogendut/NetBSD-nixbench/commit/512fe461da7bc5798fdf11d5ede91fcddf75dd9e), adds four calls to the existing
shared dispatcher and one runtime query. The [lab](../../lab/irix-tcp/README.md)
gives build/reproduction commands and exact kernel/input pins. IRIS remains
at the prior LP64 baseline; no emulator source changed in this step.
Both the LP64 and original 32-bit kernel routes retain separate outputs.

| Interface | Qualified contract |
| --- | --- |
| socket, trap 1107 | IRIX AF_INET 2, SOCK_STREAM 2, protocol 0 or TCP 6; returns a real native socket fd |
| connect, trap 1091 | Exactly 16 bytes; foreign 16-bit family translated to native length/family; network-order port/address retained |
| setsockopt, trap 1105 | Exactly one 32-bit integer; TCP level 6/name 1 and socket level 65535/name 8 translated explicitly |
| sginap, trap 1082 | Zero yields; positive signed 32-bit ticks use 100 ticks/second independently of native hz |
| syssgi, trap 1040 | SGI_SYSCONF 22, _SC_CLK_TCK 3 returns 100 |

File descriptors, waits, authorization and socket state are owned by the
native kernel. The wrappers validate foreign widths, lengths and constants
before passing native arguments. `connect` builds a zero-initialized native
sockaddr; it never passes the foreign layout or length to the native socket
implementation. Existing errno translation maps native refusal to IRIX 146.
All returns are explicitly 32-bit. Optional user tracing now includes return
values, which lets the workload distinguish a real connection result from
an unimplemented call.

The clock query was necessary for the actual application. An initial trace
showed successful socket/options/refusal but six `sginap(0)` calls: the
missing clock-rate query made Xlib compute zero delay. Original IRIX reports
100 and calls `sginap(101)`. The final kernel supplies the query and the
corresponding sleep units. The [SGI sginap manual](https://www.typewritten.org/Manual/SGI/IRIX/6.5.3f/man2/sginap.html)
describes zero as a yield and positive durations in CLK_TCK units; the
supplied installation's headers and native traces agree on 100.

## Paired behavior and deliberate limits

The original fixture source runs on both systems without libc. The reference
also uses an original assembly echo peer; NetBSD uses a native C peer.
Successful transfer checks validate both ends of an exact eight-byte payload,
including partial-read/write loops. Native getsockopt independently observes
the foreign option setters on an inherited socket, testing both enabled and
disabled values rather than accepting a successful return alone.

The foreign ABI uses five 32-bit arguments for setsockopt. Direct and indirect
o32 forms exercise stack spills; n32 uses registers and preserves a full-width
saved register. Bad stacks, negative/oversized lengths, null/high/wrapping
pointers, wrong families/options and invalid/non-socket descriptors are tested.
The native parent measures sleep duration and bounds each child. Native/vendor
controls and clean shutdown detect damage beyond the foreign process.

Of the 168 paired cases, 148 records match exactly. The other 20 preserve
the following explicit differences from broader IRIX behavior:

- IRIX accepts a datagram socket; this TCP-only implementation rejects it
  with ESOCKTNOSUPPORT. Other domains, types, flags and protocols are outside
  the supported contract.
- IRIX accepts an eight-byte buffer for the tested integer option. This
  implementation requires four bytes and rejects negative/other lengths
  with EINVAL; the reference returns EFAULT for a negative length.
- Original IRIX terminates the tested delay-slot syscalls with SIGSYS.
  NetBSD retains the already-qualified delay-slot support.

Negative sleep rejection is a separate local policy test, excluded from
those 168 paired cases. Signal-interrupted sleeps and the longest
representable duration are not qualified; no foreign signal handler support
is implied.

There is no foreign bind/listen/accept, UDP, IPv6, local-domain transport,
general socket option, nonblocking I/O or full X event-loop contract in this
checkpoint. Resource files, authentication and session integration require
separate work. The controlled native X test disables authentication solely
on its disposable guest display.
