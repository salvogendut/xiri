# Original SGI file playback on the Xiri Indy

The test uses each release's original n32 `sfplay`, `libaudio` and
`libaudiofile` as the normal `xiritest` user. The player reads the file,
loads SGI's converters, opens an Audio Library port, and submits PCM.
Prismatic's SDL disk output records the samples that reach the host. The
module is built from NetBSD-xiri `4300936187b`. The Indy kernel and the
Prismatic executable come from the preceding display-and-sound profiles.

## From the donor to the speaker

On the original 6.5.22f Indy and 6.5.30f O2, we traced a play of
`emptyDumpster.aiff`. Both donors read the file, query the master device
and request a playback port. The two Xiri targets are Indys with native
NetBSD HAL2 audio.

| Operation observed on the original donors | Xiri implementation |
| --- | --- |
| Find a port through master ioctl 2, then open `hdsp0r2` | The character device clones a private port on every open. |
| Select PCM format (29) and ring type (10) | The library can retry a mono request as stereo, as on the donors. |
| Map the queue at offset zero with `MAP_SHARED`, set its name/version (8), acquire playback (3) | A bounded anonymous mapping holds the header and the sample words. The producer advances the tail. The consumer advances the head as the native track accepts audio. |
| Fill and drain the queue | The signed sample occupies the low 24 bits of each word. The module converts to 16-bit stereo for NetBSD. Each open has a separate output track. |

The SGI sample is a 44.1 kHz mono AIFF of about 0.34 seconds. The donor
player probes a 400,024-byte mapping, then uses 352,824 bytes for its
one-second stereo queue, including the header and spare frame. A missing
converter can leave `sfplay` with exit status zero and silent output.
The release CDs include both the SGI format converter and the rate converter
requested by 6.5.30f. [Build, donor paths and reproducible audio checks](../../lab/irix-hdsp/playback/README.md).

## Output measurements

Both release-specific CDs installed twice on fresh copies of the previous
Indy display-and-sound profiles. After a cold boot, the guest's module
matched the CD, and `xiritest` played a generated
three-second stereo WAV through the original player. Its left/right tone
pairs were 440/733, 611/457 and 349/997 Hz, one second per pair. The
different frequencies identify swapped channels, a wrong sample rate and
loss of a section across queue wrap. SDL captured stereo S16LE at 48 kHz.

| At the frontend | IRIX 6.5.22f | IRIX 6.5.30f |
| --- | ---: | ---: |
| 44.1 kHz stereo, maximum absolute peak at native mixer 128,128 | 9,035 | 9,036 |
| Mono donor AIFF, lowest waveform correlation across both channels | 0.9950 | 0.9978 |
| Peak after an IRIX client set both master gains to negative infinity | 0 | 0 |
| After restoring IRIX gain to native 64,128 | Left approx. half, right full | Left approx. half, right full |

Both releases also passed the same tone-order check on a 48 kHz source.
Two concurrent copies of the original player, each carrying just one
channel at 48 kHz, produced all three pairs together at the frontend. Both
guests completed a soft power-off.

The gain test uses ordinary IRIX master-device requests independently of
SoundScheme. The separate Audio Panel Mute button still needs a UI check.
Recording, digital ports and timestamped audio/video synchronization remain
open. The measurements apply to the two emulated HAL2 Indys.
