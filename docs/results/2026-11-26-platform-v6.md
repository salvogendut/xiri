# Indigo2, Octane and O2 kernel update

These machines use the same NetBSD 11.99.11 IRIX compatibility module as each other, with a kernel built for each board. The module implements the original IRIX `utime` system call. The userspace and desktop come from the corresponding 6.5.22 or 6.5.30 disk.

## Boot a standalone updated desktop

The launchers use a private writable overlay in each bundle. Choose the IRIX release suffix `22` or `30` and run one machine from the Xiri checkout.

```sh
release=30
.work/native/xiri-ip28-v6-6.5.${release}-20261126/run-iris.sh
.work/native/xiri-ip30-v6-6.5.${release}-20261126/run-iris.sh
.work/native/xiri-o2-v6-6.5.${release}-20261126/run-iris.sh
```

At xdm, `xiritest` opens 4Dwm and `netbsdtest` opens the native NetBSD desktop. Each development password is the account name. Each bundle includes its qualification record and PNG captures of both sessions.

## Update an existing framed disk

Start with the November 22 Indigo2 DMA image or the November 23 Octane or O2 framed image. Each machine uses one update ISO for both vendor releases. Attach it to the next SCSI slot on its manual launcher. From the Xiri checkout, for example:

```sh
media="$PWD/.work/installers/sgi-platform-v6-20261126"
.work/native/xiri-ip28-dma-6.5.22-20261122/run-iris.sh --cdrom4 "$media/ip28.iso"
.work/native/xiri-ip30-frame-6.5.22-20261123/run-iris.sh --cdrom2 "$media/ip30.iso"
.work/native/xiri-o2-frame-6.5.22-20261123/run-iris.sh --cdrom4 "$media/o2.iso"
```

Choose the command matching your machine. On NetBSD, log out of the desktop before updating. As root, run:

```sh
mkdir -p /cdrom
mount -rt cd9660 /dev/cd0a /cdrom
sh /cdrom/upgrade.sh
shutdown -r now
```

After reboot, `uname -r` shows `11.99.11`, and `modstat -n compat_irix_o32` lists the boot-loaded module. To roll back, mount the same disc, run `sh /cdrom/upgrade.sh --rollback` and reboot. The previous kernel and module then boot again. Both operations check file digests, retain the pre-update files under `/var/db/xiri-platform-v6/original`, and can be repeated. If interrupted, rerun the same operation before changing direction. The per-machine CD checks the board and previous kernel before first installation.

| Machine | Kernel configuration | Boot files updated |
| --- | --- | --- |
| Indigo2 R10000, High IMPACT | `XIRI_IP28` | `/netbsd.ip28` |
| Octane R10000, Solid or High IMPACT | `XIRI_IP30_DESKTOP` | `/netbsd.ip30` |
| O2 R10000 | `XIRI_IP32_DESKTOP` | `/netbsd` and `/netbsd.boot` (ELF32) |

The module goes under `/stand/sgimips/11.99.11/modules/compat_irix_o32/`. The original 11.99.9 module stays in its own versioned directory. No PROM settings need changing.

## Guest results

The test cold-boots the installed update and the restored version as standalone CHDs. On 11.99.11 the n32 timestamp call succeeds and the filesystem reports mtime 1234567890. The restored 11.99.9 module returns IRIX ENOSYS (89). Each release goes through two consecutive updates and two consecutive rollbacks. On both generations separate xdm logins reach the IRIX and native NetBSD desktops at 1280×1024 and log out to the greeter.

Each standalone candidate was compressed and verified with chdman before boot. The platform tests used the emulator binaries already qualified for those manual bundles. ## Repeat the qualification

Build the three configurations and `sys/modules/compat_irix_o32` in the sgimips/mips64eb toolchain at NetBSD-xiri revision `4ed77b1dfd05`. Use the previous kernel SHA-256 in the corresponding framed disk's qualification record. Build each update ISO with [make-media.py](../../lab/platform-update/make-media.py). For example:

```sh
python3 lab/platform-update/make-media.py o2 --kernel "$kernel/netbsd" \
  --boot "$kernel/netbsd.elf32" --module "$module/compat_irix_o32.kmod" \
  --previous-kernel-sha256 "$previous_sha" --output "$PWD/o2.iso"
```

For Indigo2 or Octane select `ip28` or `ip30` and omit `--boot`. Build the [IRIX timestamp probes](../../lab/irix-pathops/README.md) with `python3 scripts/build-irix-pathops.py --suite utime`. Put `n32-direct` and `lab/platform-update/check-in-guest.sh` (named `check.sh`) at the root of a Rock Ridge probe ISO.

Run [check.py](../../lab/platform-update/check.py) with `--bundle` (original manual bundle), `--disk`, `--emulator` (directory with iris and iris-ci), `--media`, `--probes` and a new `--output` directory for each phase. Start with `update` on the original disk. After a successful shutdown flatten the private overlay using `chdman copy -i netbsd-xiri.chd.diff.chd -ip netbsd-xiri.chd -o candidate.chd -c zlib`, then `chdman verify -i candidate.chd`. Use `rollback` on that standalone candidate, flatten its halted disk the same way, and use `restored` on the result. Graphical checks use 4Dwm as `xiritest` and ctwm as `netbsdtest`. The functional check sets a file's mtime to 1234567890 as an ordinary user through the n32 IRIX system call. Physical SGI hardware needs separate testing.
