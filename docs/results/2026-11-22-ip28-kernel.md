# Native NetBSD IP28 boot, 2026-11-22

Indigo2 IP28/R10000 now boots a native NetBSD kernel through the BSD disk
loader, mounts FFS, runs a single-user shell, reads and writes files, exchanges
Ethernet packets and halts cleanly back to the PROM. This passes with separate
Xiri disks carrying the 6.5.22 and 6.5.30 resource lines.

This is the first native platform checkpoint. It is **not an IMPACT Xiri
desktop**: the new kernel has no qualified IMPACT display/input path or matching
IRIX compatibility module. The working native IRIX IMPACT disk and both
qualified Indy desktop images remain unchanged.

## Source and implementation

NetBSD commit
[`68d928aee10`](https://github.com/salvogendut/NetBSD-xiri/commit/68d928aee10b7fde88fcb3f05d98fee041d02c3c)
is integrated and pushed to `xiri`. Work used `topic/sgimips-ip28`, based on
`b84b5316b3a`, in an isolated worktree. The main NetBSD checkout remains on its
separate `topic/sgimips-octane` branch. Existing detached reproduction trees
retain their pins.

| Area | Change |
| --- | --- |
| Kernel configuration | `GENERIC64_IP28`: N64, R10000, ARCS64, text at `0xa800000020080000`, native serial/SCSI/Ethernet devices; no ELF32 wrapper |
| Firmware ABI | `dev/arcbios/arcbios.h` and `arcbios_calls.S`: 64-bit firmware longs, pointers and vector entries; N64 call wrapper; existing ARC32 and standalone layouts preserved |
| Early startup | `locore.S`, `sgimips/machdep.c`, new `arcs64.[ch]`: clear BSS, own bootstrap stack, full-width arguments/bootinfo, checked firmware layouts |
| High-address kernel | `Makefile.mips`, `mips_machdep.c`: opt out of compact symbol addresses/ELF32 wrapping and reserve the actual XKPHYS physical kernel pages |
| Exceptions and TLB | `mipsX_subr.S`: full-width targets through reserved low-vector cells; preserve KX during interrupt-disabled sections and return correctly to user code |
| Stub optimization | `mips_fixup.c`: leave full-width XKPHYS indirect stubs intact; the existing compact-address optimizer remains active for legacy kernels |
| IP28 board attachment | Reuse the Fullhouse MC/GIO/HPC3/INT2, native SCC serial, IOC and RTC attachment paths; recognize IP28 during clock setup |
| R10000 cache geometry | Read secondary-cache size/line geometry from CP0 Config: the tested machine reports 1 MiB, 128-byte lines, two ways |

Portable high-address pieces were adapted from the project's existing Octane
topic. Octane board support was not merged in this cycle. No IRIS production
code or vendor binary was changed.

The firmware layout follows public ARCS declarations, including the
[public Linux ARCS header](https://android.googlesource.com/kernel/common/+/ad6c13e25f89/arch/mips/include/asm/sgiarcs.h).
The R10000 cache decoding was checked against the
[public Linux implementation](https://github.com/torvalds/linux/blob/master/arch/mips/mm/c-r4k.c)
and NetBSD's existing CP0 field definitions. This work uses public interfaces,
project source and observed firmware behavior.

## Validation

Environment: IRIS Indigo2 IP28, R10000 at the emulated 195 MHz clock, banks
`[512,512,0,0]`, High IMPACT, embedded PROM, visible emulator window and serial
console. The kernel reports 1,073,725,440 bytes of physical memory after early
reservations. Build: existing NetBSD GCC 14.4.0 cross-toolchain, isolated output,
two compilation jobs. The kernel and legacy Indy builds ran sequentially.

The rebuilt standalone loader targets also compile, and the vendor-free
boot64 data/BSS/bootinfo handoff fixture passes. These are native platform and
IRIX-shell regression checks; they do not repeat graphical desktop qualification.
The [JSON record](2026-11-22-ip28-kernel.json) retains revisions, hashes, exact
check results and local evidence paths.

The first networking probe ran before NetBSD cleared its address's
`TENTATIVE` flag. Waiting with `ifconfig -w 20` resolves that test setup issue;
no Ethernet driver fix was needed. The serial harness also accepts the
kernel console's LF/CR ordering around success markers and requires the real
shutdown sequence, not the earlier userspace `halted by root` message.

IRIS upstream was checked at `6ec1ebf379228d572026a9ae8d291511ed28af74`, with
no incoming commits. Integration remains `eb21c6ec`; the retained accelerated
binary is from `0bc52567`, with SHA-256
`6359dc8381fe77f17fd329cf2be38967a1486ba56e4d14e6648c7d0a0297eec7`.
The later fork commit changes only the previously documented IMPACT regression
test, so no emulator rebuild was needed for this cycle.

## Retained artifacts and manual use

The native kernel bundle is `.work/native/netbsd-ip28-kernel-20261122/`, with
`netbsd`, debug symbols/map, `GENERIC64_IP28`, the tested `ip28boot`, and the
Indy regression kernel. Kernel SHA-256:
`02297b3d80dac23c86af839a4a7b82acf9d3aa7d7220ec4cd65116bdec419fde`.

Separate manual disks:

- `.work/native/xiri-ip28-6.5.22-20261122/netbsd-xiri.chd`
- `.work/native/xiri-ip28-6.5.30-20261122/netbsd-xiri.chd`

Each bundle has a launcher, saved firmware state, checksum/qualification
record and serial-console instructions. From the Xiri repository:

```sh
.work/native/xiri-ip28-6.5.22-20261122/run-iris.sh
```

In another terminal, connect with `nc 127.0.0.1 19230`; choose PROM option 5,
then `boot`, then Return for `/bin/sh`. The 6.5.30 bundle uses serial port
19330. If execution is paused, type `start` at the IRIS monitor. These images
use `console=d`: the NetBSD console appears in the serial terminal.

Use `mount -u -w /` for writes, then `/sbin/halt` before closing IRIS. Manual
changes go to a local overlay. The candidates preserve `/netbsd` and the old
module, while `/netbsd.ip28` is the new boot target. They start single-user;
starting the inherited xdm configuration is not a supported IP28 desktop path.
See [the fixture guide](../../lab/ip28-kernel/README.md) for the compact PROM
settings, build commands, image preparation and regression procedure.
