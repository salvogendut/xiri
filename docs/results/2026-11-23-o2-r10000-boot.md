# O2/R10000 disk boot on IRIS

The emulated O2/R10000 cold-boots NetBSD 11.99.9 from SCSI target 1, mounts FFS on `sd0a` and runs the IRIX 6.5.22 and 6.5.30 desktops. The kernel reports `SGI-IP32` and attaches both AIC-7880 controllers. Each disk loads `compat_irix_o32` and runs the original `/emul/irix/bin/sh`.

## Try the O2

Run one launcher from the Xiri checkout. Each bundle has its own disk, O2 PROM flash settings and writable overlay. The ROM starts automatically. Boot messages go to the first MACE serial port and Xorg uses the O2 display. At xdm the IRIX account and password are both `xiritest`. The NetBSD account and password are both `netbsdtest`.

| IRIX software | O2 launcher | Serial console |
| --- | --- | --- |
| 6.5.22 | `./.work/native/xiri-o2-xdm-6.5.22-20261123/run-iris.sh` | `telnet localhost 20823` |
| 6.5.30 | `./.work/native/xiri-o2-xdm-6.5.30-20261123/run-iris.sh` | `telnet localhost 20831` |

The username and password labels at xdm are unreadable on the CRIME display. Type the username, press Enter, type the password and press Enter again. Run `shutdown -h now` as root and wait for the PROM menu before closing IRIS.

## Desktop checks

Both disks reached 1280×1024. After login as `xiritest`, the window tree included Toolchest, winterm, xclock and a 16-page Icon Catalog. The GBE framebuffer captures show File Manager and the desktop icons. Logging out returned to xdm. A second keyboard login as `netbsdtest` started NetBSD ctwm. ## What changed since the interpreter check

The [November 15 O2 result](https://github.com/salvogendut/NetBSD-xiri/blob/33b5dda6a45/xiri/platforms/2026-11-15-results.json) reached a read-only single-user shell by network-loading the kernel. That run verified the IRIS wide MACE PCI fix. The November 23 checks reused the IP32 kernel and tested both module versions with the R10000 JIT binary used for the Octane. IRIS upstream `a05289ef` was already integrated in fork commit `08e53ba7`. A separate interpreter run using the same fork revision and 6.5.30 root also passed the single-user check.

For each release, a private copy of the corresponding November 23 Octane root supplied the installed applications and NetBSD userland. In single-user mode we installed the IP32 kernel as `/netbsd`, its ELF32 wrapper as `/netbsd.boot`, the compatibility module under `$(sysctl -n kern.module.path)/compat_irix_o32/`, and the O2 Xorg configuration at `/usr/local/share/xiri/xorg.conf`. We installed the stock NetBSD loader with `/usr/mdec/sgivol -q -w boot /usr/mdec/ip3xboot /dev/rsd0c`. The O2 PROM uses partition 8 for the loader and partition 0 for `netbsd.boot`. After a clean halt, each disk was flattened into a separate standalone CHD and passed raw and overall CHD verification.

The final cold boots used the standalone disks without TFTP or installation media. Both O2 configurations have one R10000, 256 MiB, CRIME graphics, and MACE PS/2 keyboard and mouse. For automated graphics testing the launch configuration keeps `headless = false` and enables CI offscreen capture. On O2, selecting headless removes both PS/2 devices.

## Why the 6.5.30 shell worked before its desktop

The November 14 O2 module could execute the original IRIX shell on either root. On 6.5.30 the same module rejected 4Dwm with `Cannot execute ELF binary`. The 6.5.30 n32 interpreter uses MIPS IV flags. Its admission fix landed after the O2 package was built. [NetBSD change](https://github.com/salvogendut/NetBSD-xiri/commit/93a258077244ea6e6a1a43a9d2e8b8fa41aa6555)

We loaded the old and current modules in turn on the same running O2 kernel, using the same 4Dwm executable and an unused X display. With the current module, 4Dwm executed and reported that it could not open the requested display. The 6.5.22 executable reached that point with either module. All 172 imports of the current module resolve against the retained IP32 kernel. The final disks use that module on both release lines. We also tried `Xft.render: false` in `/etc/xiri/xdm/Xresources` on both disks. The resulting captures still show missing or obscured greeter text.

## Reproduce the cold-boot check

```sh
IRIS_NO_IDLE=1 python3 lab/irix-o2/check-disk.py \
  --bundle .work/native/xiri-o2-xdm-6.5.30-20261123 \
  --emulator .work/emulators/iris-ip30-jit-08e53ba7 \
  --output .work/o2-recheck-6.5.30
```

Use the 6.5.22 bundle and a fresh output directory to check the other release. The check copies the CHD and flash, attaches an overlay, reads guest state over serial, and sends login keystrokes through the emulated keyboard. Physical hardware, sustained storage writes and network traffic need separate qualification. [O2 kernel and build provenance](../../lab/irix-o2/README.md)
