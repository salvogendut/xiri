# Original IRIX inst on the clean Indy release lines

SGI's original `inst` installed, recorded and removed Freeware software on
both Indy release lines. With Foundation and overlay media available it also
extracted xmahjongg 3.6.1 and recorded its subsystem. The surrounding base
installation stopped at IRIX device setup. Each test used a private v4 disk
copy and installer binaries from the matching original-media donor.

## System changes

The fault occurred in `libinst` while converting a disk-size value. These
Indy processors hand large 64-bit integer conversions to software. The
MIPS exception handler in the NetBSD fork dispatched this instruction to
SIGILL. The new handler converts the signed value in the process's saved
FPU context, observes all four rounding modes, and handles both o32
register pairs and n32 wide registers. NetBSD fork commits `47cfb82acb4`
and `5071d8c7018` contain the FPU and module changes, respectively.
Each CPU passed 52 conversions per ABI, including the rounded result,
sticky flag and exception cause. Enabling the inexact trap delivered SIGFPE
in both ABIs. A branch-delay conversion resumed at its branch target.
The file controls observed the previous umask and mode 0750 for a new
file requested with mode 0777 under umask 0027.

The IRIX module also implements `creat` and `umask`, and maps `O_SYNC`,
`O_DSYNC` and `O_RSYNC` using the SGI definitions. Without those flag
mappings the vendor installer reported `Can't write to target directory
/emul/irix/var/inst/: Invalid argument` and opened the target read-only.
With them it writes its own `INSTLOG`, preferences and temporary lock.

## What the installer found

The [media builder and guest commands](../../lab/irix-installer/README.md#repeat-the-clean-indy-installer-check)
verify 30 donor paths per release and add the seven missing from that
release's desktop payload. No donor installation history is staged.
The package source is the user's May 2004 Freeware CD 4; its descriptors,
inventories and compressed payloads are checked against the [media pins](../../lab/irix-installer/inputs.json).

On each target, `go` refused the unmet SGI prerequisites. Quitting with
selections pending prompts for confirmation, which timed out in an initial
noninteractive run. Repeating with `keep *` before `quit` exited zero,
released the lock, and left the original `versions` report empty for
`fw_xmahjongg`. The full game install, original hooks, catalog launch and
removal require a target with genuine base packages.

Foundation 1 supplies all three direct prerequisites. Its `eoe.sw.base`
inventory contains 3,864 distinct pathnames, including `etc/passwd`,
`etc/group`, `sbin/sh` and `sbin/init`. Selecting the three subsystems with
the corresponding 6.5.22 or 6.5.30 overlay resolves the game's direct
complaints and brings in `eoe.sw.efs` and `compiler_eoe.sw.cpp`.
The latter is present on Foundation 1 and on each release's second overlay
disc. This matters for Xiri because the native desktop currently provisions
the account map and relies on a selected subset of the donor's files.

A separate control selected only `fw_common.sw.selections`. Both vendor
installers reported zero conflicts and extracted the `gimp` selection file
with SHA256 `0f82722b11f22c7c3880b0c2b715d4b80f4c9b3136051421c668b7627f13fbf4`.
Both then reported **Unable to update installation history for fw_common**.
The interrupted operation left a checkpoint and temporary per-product data.
The vendor `versions` command reported no installed selection, and a removal
request left the extracted file in place. Files on disk and exit status zero
are insufficient to certify the package lifecycle.

Both traces showed IRIX `fsync` (1146) returning `ENOSYS` on the temporary
product and orphan history files. NetBSD fork commit `da98b7d4268` supplies
that call. On fresh roots, both installers then wrote `var/inst/hist` and
renamed the per-product file to `var/inst/fw_common`. SGI `versions` listed
`I fw_common`, the sample digest matched, and original `inst` removal
cleared the product row and deleted the sample. Both operations reached
`Checking dependencies`.

## Original game distribution

The [media builder](../../lab/irix-installer/README.md#repeat-the-clean-indy-installer-check)
can include four SGI distributions from Foundation 1 and matching overlays
1 and 2. On each release, all 24 files matched the media used by the guest.
SGI's resolver accepted the eight base subsystems, `fw_common.sw.index`
and `fw_xmahjongg.sw.xmahjongg` together with **No conflicts**.

On each empty alternate root SGI wrote a 252,672-byte executable, SHA256
`35253008a6d31ad6c4589c622146bcd0ae781488bc5d7872a4114b888e1edb59`. Its
own `versions` listed the product, image and subsystem as installed. The
base installation then stopped at the original `eoe.sw.base` post-install
command `cd $rbase/dev; ENV= ./MAKEDEV`. The file existed. Its interpreter
was `/sbin/make`, absent from the NetBSD host and the incomplete target.
Running the release's original make with `-n` displayed the proposed
SGI console, memory and disk device nodes, and a call to `/etc/devnm /`.
Those major/minor numbers belong to the IRIX kernel.

Recovery offered to run the queued exit commands. With CD 4 as the removal
source, SGI removed the game on both targets. The executable disappeared
and `versions` returned no game rows. The incomplete base had no
`iconcatalogedit` of its own, so this trial supplies no catalog-launch
evidence. The game distributed here is absent from the clean v4 imports.

The first base trial also reported ownership failures on symbolic links.
SGI's own `chown -h` reproduced missing syscall 1178 on both releases.
NetBSD fork commit `c7e2ed055ca` implements `lchown`. On each CPU root
assigned a link and a dangling link to uid/gid 1234 while the target file
retained uid/gid 0. An ordinary user's attempt to change the link back to
root returned `Operation not permitted`.

## Icon Catalog registration

On a second alternate root, we supplied the matching desktop libraries,
SGI's original `iconcatalogedit`, the Xiri account files and the guest's
native null and zero devices. The root initially contained neither the
game nor a Freeware page or installation history. SGI's recovery menu
can run outstanding package exit commands after the base transaction
stops. On the first attempts it reported success even though both the
catalog helper and its `-help` command died with SIGSEGV.

The helper's writable ELF segment starts at `0x10013000` and ends at
`0x10014000`. SGI libc successfully requested a break of `0x10016000`,
then faulted writing the first byte of the new heap page at `0x10014000`.
The fault PCs in the two releases were `0x0fa539ac` and `0x0fa46d30`.
The Xiri module now records the start and size of the data segment in
native pages. Both original helpers then printed usage on request.

On another fresh run SGI's queued exit commands created
`usr/lib/desktop/iconcatalog/pages/C/Freeware` in the package root. Both
releases produced `FreewareRelnotes` and the `xmahjongg` link. The latter
contained the full alternate-root path to the installed executable.
The installer still reported the separate `eoe.sw.base` device setup failure.

Two read-only null mounts exposed the package's `usr/freeware` and its
generated Freeware page to the live Xiri desktop. The native namespace
also had `/usr/freeware` pointing at the installed tree. The older trial
that exposed just the tiles directory through a private link failed with
a missing `thick` tileset. The mounted package supplied the original
20,418-byte `thick.gif` at the path the game opens.

Both double-clicks started the generated catalog path as uid 1234 and
opened a 1006×614 `XMahjongg` window with a rendered board. The Freeware
page showed generic file artwork for the game. The fork's heap fix
`6e9a69e852f` also passed all 100 executable-layout cases as root and
as uid 1234 on each Indy, including writes to both ends of the first
heap page.

On both releases clicking Hint changed the game-window pixels and the
Quit button closed the client. A second xdm login launched the game
again from the same catalog entry. Original `inst` removal then
cleared the executable, SGI's catalog link, the rule source, and the
open and closed icon files. `versions` reported no game rows. The
Freeware page still showed its independent release-notes entry. Native
`netbsdtest` then reached ctwm and UXTerm at 1280×1024.

The application transaction installed `xmahjongg.ftr`, `xmahjongg.open.fti`
and `xmahjongg.closed.fti`. In a separate target, running the original
filetype Makefile with SGI make, `fftr` and utilities from the verified
base media returned zero on both releases but still produced build
errors. The shell could not run the static `grep`, `sed`, `cp` and `cat`
helpers, `touch` reported unsupported timestamp changes, and
`/usr/sbin/ftr2mime` was missing. Compiled game artwork remains open.

The [release ledger](2026-11-24-indy-inst.json) records the matching
fork revision, module and payload hashes, loader checks and application
outcomes. The published v4 test CHDs retain their previously qualified kernel.
