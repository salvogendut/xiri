# Measured IRIX pipe support

IRIX trap1042 now dispatches to native NetBSD `sys_pipe`. The call takes no
kernel arguments and returns its read/write descriptors in V0/V1; the original
libc wrapper copies those values into the caller's array. Native pipe
allocation owns descriptor limits, rollback and lifetime. This adds no new
core hook for the intended compat_linux-style loadable-module target.

The [independent qualification](2026-11-01-irix-pipe.json) passes **220 native
records and 44 native/vendor controls** against **88 original-IRIX records**.
Every recorded word matches exactly, without error or descriptor
normalization. See the [lab and reproduction commands](../../lab/irix-pipe/README.md)
and [decoded original oracle](../../lab/irix-pipe/reference.json).

## Contract and coverage

The supplied IRIX 6.5.22m installation returns one read-only and one write-only
endpoint, both initially without close-on-exec. The syscall ignores the user
argument registers, including NULL, invalid high/wrapped addresses, valid
sentinel storage and read-only storage. Two-register results, untouched
sentinels, identities and unused record words are checked under both o32/n32,
direct/indirect dispatch, and UID0/UID1234.

The lifecycle cases check partial reads, byte content, EOF after the last
writer closes, dup ownership, reuse of descriptor zero, EBADF on reverse
operations, EAGAIN on an empty nonblocking pipe, inherited fork endpoints and
reaped child status. With SIGPIPE blocked, writing without a reader returns
EPIPE. This does not establish foreign signal-handler delivery or restoration.

With RLIMIT_NOFILE=32, fixtures fill all 29 available slots. Pipe returns EMFILE
with no slots free and with one slot free. A subsequent dup obtains the freed
slot, proving the failed second allocation did not leak the first descriptor.
After a second slot is freed, pipe succeeds using both slots. Native `sys_pipe`
writes return registers only after successful `pipe1` allocation, preserving
the measured V1 sentinel on errors.

Independent native controls exercise pipe I/O, nonblocking reads, forked
writers, EOF and allocation rollback before/after the foreign matrix. Existing
native o32 and vendor asa/echo programs also remain passing controls. The
native group-owning runner verifies complete group removal after each foreign
execution; the fork case explicitly reaps its child.

## Limits and upstream

STREAMS operations, poll translation, pipe capacity/atomicity under contention,
asynchronous I/O, foreign signal handlers and physical hardware remain outside
this qualification. Supporting pipe does not by itself establish full file-
manager or desktop behavior. The `sgikopt` result is not changed or faked.

IRIS upstream was fetched at the start of this cycle. `upstream/main` is still
`f17b4d3bc1663efd02f93a5e0e4811eebba510c8`, already integrated into fork `xiri`
at `087d250ab25884baaf03cc998377f75711fe5aa4`; no merge or new emulator build was
needed. The shared IRIS checkout's unrelated `perf/sgiemu-port` edits are left
untouched. Guest tests retain the qualified emulator
`9df1df14334838a989253efefe26f0547e6da592`.


## Desktop harness diagnostics

The first desktop retry requested 180 seconds from the unchanged supervisor,
whose accepted maximum was 120 seconds. It returned status2 before launching
any client. A parallel ordinary attempt was interrupted during helper
compilation after this was found. Both guests halted cleanly; their frozen
harness/guard sources and result hashes are retained in the
[diagnostic record](2026-11-01-irix-pipe-diagnostics.json). They are not passing
or failing application evidence.

The corrected observer uses a separate guard copy with only its duration
ceiling raised to 180 seconds, preserving the earlier qualified source. It
first runs the pinned native o32 ABI probe through that guard at the requested
duration and checks its exit37, marker output and cleanup before launching the desktop.


A subsequent pair accepted the guard duration but stopped at its startup
control: `/bin/true` does not exist in this NetBSD guest, producing ENOENT
before any desktop launch. Both halt cleanly and are retained in the same
diagnostic record. The final control instead installs the already verified
native ABI probe into the readable session directory and checks its known
exit37 and marker. These harness errors do not alter the passing pipe matrix.
