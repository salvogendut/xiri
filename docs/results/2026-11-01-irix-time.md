# IRIX time support and ticking xclock

NetBSD `xiri` now supplies the measured IRIX `time(1013)` and
`gettimeofday(1128)` interfaces at source
`76de548ab644cb471f4c5b97ec89671c1d385c5b`. The original analog and digital
xclock display current time and advance. The digital
[before](images/2026-11-01-irix-xclock-time-before.png) and
[after PNG](images/2026-11-01-irix-xclock-time.png) show
**Sun Nov 1 19:23:07 2026** and **19:23:11**, respectively, in UTC.
This replaces the earlier epoch-time display; vendor binaries are unchanged.

## Measured interface

The installed IRIX 6.5.22m reference produces 192 records across 24 variants,
both ABIs, direct/indirect dispatch and root/UID1234. The
[retained reference](../../lab/irix-time/reference.json) includes all words,
source hashes and the result hash. The independent checker verifies the
contract rather than assuming the old compatibility implementation is exact.

- Raw `time` returns seconds in V0, preserves V1 and ignores pointer arguments.
  Even null, invalid, read-only and page-crossing destinations are untouched.
  The libc API's optional output pointer is not a kernel copyout argument.
- `gettimeofday` writes eight bytes: 32-bit seconds and 32-bit microseconds.
  Success returns zero and preserves V1. It takes one destination; an invalid
  second argument is ignored. Unaligned destinations work.
- Null, inaccessible and read-only destinations yield EFAULT14. At a protected
  page boundary, the already written four-byte or one-byte prefix remains.
  Guard bytes outside the written extent are unchanged.

Each record includes before/after time calls, two guarded timeval samples,
identity and a ten-tick delay. Independent guest UTC dates bracket the matrix.
The checker validates date bounds, ordering, microsecond ranges, advancement,
all register fields and all guarded destination bytes. Different boots have
different absolute times; those values are not normalized into a purported
exact timestamp match. Page size is checked against the actual kernel.

## Implementation and checks

The adapter uses native `microtime` and an explicit pair of 32-bit fields,
never the native LP64 timeval layout. Native `copyout` supplies unaligned and
partial-fault behavior. The raw time entry consumes no arguments; gettimeofday
consumes one. Both direct and checked indirect dispatch use the same handlers.
No core kernel hook or native time-setting path changes. Deployment remains
the built-in personality pending the planned compat_linux-style module.

The [ABI report](2026-11-01-irix-time.json) covers **480 native records and
44 native/vendor controls**:

| Kernel / mode | Run under `.work/irix-time/runs` | Records | Controls |
| --- | --- | ---: | ---: |
| LP64 CI | `lp64-ci-mtxmm6xh` | 192 | 16 |
| LP64 ordinary | `lp64-ordinary-5gahy6td` | 192 | 16 |
| o32 CI | `o32-ci-wdxai6sq` | 96 | 12 |

Native time/select checks and established native o32, vendor o32 asa and
vendor n32 echo controls run before/after the foreign matrix. Every fixture
exits normally, emits exactly 256 bytes and leaves no process group.
[Twelve altered records](2026-11-01-irix-time-qualifier.json) are rejected,
including epoch/frozen output, invalid microseconds, wrong return/identity,
missing or overlong copyout and damaged guards. Both kernels build cleanly
in new output directories, sequentially with two jobs. The initial run JSON
retains a copied `F_TIME descriptor allocation` label in its pin description.
The corrected pins name time/gettimeofday; qualifiers permit only that known
label alias and require every source/configuration/binary field to match.
Raw observations and result files are preserved unchanged.

The reference run is `.work/irix-reference/time-records-runs/ci-cmkx7nzx`,
a disposable clone of the stopped F_DUPFD reference. Its original binaries
are frozen and checked after upload; compressed archive output is checked
against the result JSON. The reference and all accepted native guests halt
cleanly; the final host process check finds no remaining IRIS instances. The image's previously documented XFS/startup alerts remain outside
filesystem qualification.

## Original xclock

The [xclock report](2026-11-01-irix-xclock-time.json) checks eight launches:
analog and digital, root and UID1234, in CI and ordinary IRIS. Each launch
runs for a bounded 18 seconds, with an intentional watchdog and whole-group
cleanup. Native X windows and native/vendor execution controls pass before
and after. The two runs are:

- `.work/irix-xclock-time/runs/ci-h9j93z0m`
- `.work/irix-xclock-time/runs/ordinary-2qota0w8`

The environment sets `TZ=UTC0`; standard X colors avoid dependence on SGI
color names. The existing pinned executable, runtimes and app-defaults are
reused without additional imports. Each window is viewable, the time returns
match the guest's UTC date, and successive captured pixels change. A further
capture after `xrefresh` verifies continued rendering after Expose. Digital
frames are also [visually reviewed](2026-11-01-irix-xclock-time-visual.json) for
actual date/text advancement, including a minute rollover. All displayed
seconds occur in successful time returns and within guest-date bounds.
Changing pixels alone would not establish correct displayed time; the checker
also rejects a blank client interior after redraw.

The two linked PNGs are lossless conversions of the CI root digital frames.
The raw XWD frames and traces remain private in the run directories. These
are actual original-client captures under native Xvfb, not reconstructed
images or a claim about an entire desktop session.

## Remaining work

Current positive signed32-bit dates and bounded UTC sessions are qualified.
Pre-epoch dates, the 2038 boundary, wall-clock adjustment, timezone/DST,
longer sessions and physical hardware remain unqualified. Foreign signal
handlers and the existing broader desktop limits are unchanged.

The [installer retry](2026-11-01-irix-installer-time.md) confirms three time
and 54 gettimeofday successes, but still reaches its watchdog. Its native
helper searches omit `/bin`; helper arguments/output and completion handling
are the next investigation. There is no distribution-reading, installation
or Freeware catalog-entry success yet. The [lab](../../lab/irix-time/README.md)
contains reproduction commands, record layout and resource bounds.
