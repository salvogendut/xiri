# Native IP28 xdm login, 2026-11-22

Both IRIX release lines now boot through NetBSD rc.d into a full-size native
xdm greeter on IP28/High IMPACT. `xiritest` selects the IRIX 4Dwm desktop;
`netbsdtest` retains NetBSD's standard ctwm desktop. Each line passes an IRIX
login, logout, native login, logout, and another IRIX login/logout, followed by
orderly shutdown. Xorg and captured scanout are 1280×1024 throughout.

The matching kernel/module and display driver are unchanged from the
[IP28 IMPACT checkpoint](2026-11-22-ip28-impact.md). This cycle changes the
image's boot configuration and adds qualification fixtures. Native xdm/PAM,
system Xsession, account passwords and imported IRIX programs are unchanged.

## Boot configuration

With serial B as the console, the kernel does not allocate graphical screen 0.
The manual desktop wrapper explicitly creates it. Normal xdm startup instead
uses the existing NetBSD `wscons` service: `/etc/rc.conf.d/wscons` enables it,
and `/etc/wscons.conf` creates `screen 0 - vt100` before xdm starts.
`ttyE0` remains disabled as a getty; `ttyZ0` remains available for administration.

The existing Xorg configuration uses native `wsfb`, with the same display mode,
fonts and input devices. The preparation script removes stale Newport names
and its irrelevant acceleration option. `/etc/modules.conf` loads the matching
`compat_irix_o32` personality during startup; the qualification sees it as a
filesystem module at securelevel 1. PTY preparation, FAM and rpcbind run through
their existing services, and xdm owns X authorization and server resets.

`lab/ip28-kernel/prepare-xdm.sh` prepares a private overlay of each qualified
IP28 image. It does not create accounts or select Xiri for every user. The
existing `.xsession` chooses Xiri for `xiritest`; the absence of `.xsession`
leaves `netbsdtest` on NetBSD's normal desktop.

## Qualification

The full runs are `.work/ip28-xdm-20261122/qualify2-6.5.22/` and
`qualify2-6.5.30/`. Both completed uninterrupted, including clean unmount and
return to the PROM. An earlier pair stopped because the harness matched the
printed `ddb.onpanic` sysctl name as a panic; the detector now distinguishes
that setting from an actual panic. Those failed attempts are not counted.

coverage of ctwm's Quit menu or repeat the earlier IRIX menu-action tests.
The run records preserve user/session evidence, source hashes and PNG hashes.

## Manual images

Separate automatic-boot bundles are:

- `.work/native/xiri-ip28-xdm-6.5.22-20261122/run-iris.sh`
- `.work/native/xiri-ip28-xdm-6.5.30-20261122/run-iris.sh`

Run one and press Ctrl-P if the emulator starts paused. No PROM command or
manual desktop launcher is required. The saved settings select `boot`,
`netbsd.ip28`, `OSLoadOptions=auto`, `AutoLoad=Yes`, and `console=d`.
Boot messages remain on serial B until the graphical greeter appears.

Use the existing public lab credentials `xiritest` / `xiritest` for IRIX, or
`netbsdtest` / `netbsdtest` for ctwm. Root remains available without a password
on serial B (`19630` for 6.5.22, `19730` for 6.5.30); the native user can also
use `su -`. Use `shutdown -h now` before closing the emulator. Manual changes
go into the bundle's own private CHD overlay. Each bundle includes `README.txt`
and `qualification.json`; [fixture instructions](../../lab/ip28-kernel/README.md#native-xdm-startup)
describe reproduction.

## Packaged boot and cleanup

Both standalone CHDs pass `chdman verify`, then a fresh automatic disk boot
using the bundle's saved firmware settings. These final checks attach no test
CD and issue no PROM commands. They verify the matching kernel/module hashes,
service state, securelevel, 1280×1024 greeter, native I/O and orderly halt.
The actual rc.d order is modules → wscons → xiri_devices → xiri_famd → xdm.
See the [machine-readable record](2026-11-22-ip28-xdm.json) for hashes and
separate preparation, full-session and packaged-boot results.

Private test overlays, fixture media and duplicate/failed PNGs are removed,
about 28.3 MiB of allocated files.
The new CHDs, firmware, compact logs/source snapshots and selected screenshots
are retained, along with previous qualified images. All owned IRIS instances
and the packaging container started for this cycle are stopped. No kernel
build, emulator build or temporary fork worktree was needed.
