## Implementation and evidence

The validated foreign exec maps a private zero-filled native page at 0x200000
and initializes the measured system prefix at +0xe00 using explicit 32-bit
words. Original measurements establish PID, initial FP flags (o32 0 / n32 4),
and CPU PRId (R4400 0x440). Remaining inspected bytes start at zero.
Normal fork preserves the user area through COW and updates only the child's
PID. Exec resets deliberately corrupted PID/user bytes. Traditional signal-mask
changes leave the inspected PRDA hold fields zero, matching the reference.

The licensed historical NetBSD definitions supply layout context. Its older
PRId initialization was not copied: paired original runs show CPU identity,
not PID. The [SGI sproc manual](https://techpubs.jurassic.nl/manpages_0530/cat2/standard/sproc.html)
describes PRDA and ordinary fork behavior. Share groups, threads, scheduling
hints, general FP control and user-managed PRDA signal holds remain unsupported.

A damaged or read-only PID mapping makes fork return EFAULT before creating a
child. This is explicit native policy. Native exec removes the foreign mapping
and retains the usual native page-zero guard. LP64's extra half-page is zero.

## Application follow-up

The first live run `prda-ci-v52olycp` remains alive for its 30-second bound and
reparents native windows. Its pointer-focus check fails. Trace evidence reveals
EACCES reading the original `system.4Dwmrc`: copies onto pre-existing files had
preserved restrictive modes. Resource bytes were correct, but permissions
needed explicit restoration just as the ELF files had earlier required it.

The [application evidence](2026-11-01-irix-4dwm-prda.json) binds these observations, original byte hashes and native controls.

The corrected CI and ordinary runs (`resources-ci-lfc6jflb` and
`resources-ordinary-ftotu8vv`) make the four original files mode 0444 and give
UID1234 a private writable HOME. The configuration-open warning disappears.
They reach additional session-saving activity but fail to reparent new native
windows within the bound. Both remain alive, clean their descendants and halt.
The trace includes unimplemented rename/unlink/fsync calls and temporary-file
attempts; this is a later startup boundary, not a qualified desktop.

The original application also creates a Trusted Path Manager panel despite
X.org lacking SGI-AccessControl. Feature-query behavior still needs isolation.
The follow-up isolates window management with session saving disabled and
checks the combined original applications. Full desktop services and session
restoration remain unqualified.
