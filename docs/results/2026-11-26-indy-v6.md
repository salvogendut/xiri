# Clean Indy v6 images and in-place kernel updates

The 6.5.22f R4400 and 6.5.30f R5000 images boot the IRIX timestamp module
from the base NetBSD desktop package. The optional Mozilla component owns
the browser and its hostname service. You can update a v5 disk in place
with its release-matched CD or start from a fresh CHD.

## Try the desktops

From the Xiri checkout, run the launcher for the IRIX release you want:

```sh
.work/images/xiri-clean-indy-6.5.22f-v6-20261126/run-iris.sh
```

```sh
.work/images/xiri-clean-indy-6.5.30f-v6-20261126/run-iris.sh
```

At xdm, log in as `xiritest` for the IRIX desktop or `netbsdtest` for native
NetBSD ctwm. Each test password equals its username. Both launchers use a
writable overlay for the manual session. [Update, rollback and fresh install](../NATIVE-PACKAGE.md#install-or-update-an-indy-to-v6).

The graphical launcher enables the Indy HAL2 controller with
`no_audio = false` in `iris.toml`. Earlier copies can use the same
setting with their existing CHD. [Native audio and SGI control panel checks](2026-11-26-indy-controlpanels.md).

## Qualification

Each new CHD comes from a new installation on stock NetBSD 11.0/sgimips
userland and X sets. The bootstrap installed the 11.99.11 kernel, its PROM
boot file and its module, rebooted and checked all three file hashes and the
loaded module. The installer ran twice on each release. The CHD packager
verified the compressed disk and compared its data SHA-1 to the halted raw
disk before the graphical cold boot.

| Guest check | Updated v5 | Rolled back to v5 | Fresh v6 CHD |
| --- | --- | --- | --- |
| Freeware wget 1.8.2 as `xiritest` | Original 10 bytes, HTTP mtime 1234567890 | Original 10 bytes, v5 timestamp warning returns | Original 10 bytes, HTTP mtime 1234567890 |
| 4Dwm login, original shell, logout | Passed | Passed | Passed |
| Mozilla opens a local HTTP document via its location bar | Passed | Passed | Passed |
| Separate `netbsdtest` login, ctwm and xterm, logout | Passed | Passed | Passed |

Both updates and both rollbacks were repeated. After rollback, the desktop
receipt, Mozilla receipt and browser ownership plan matched the saved v5
files byte for byte. Account files, module and service configuration and the
user's selected session survived both operations. The fresh-image tests
also removed and reinstalled Mozilla from the v6 CD and verified the kernel,
PROM boot file and module at each step.

On the rolled-back 6.5.22f profile, Mozilla 1.0.1 first displayed a blank
document at the entered URL. An uncached reload displayed the local page.
One cold-boot login to ctwm also needed the test account typed again after
xdm showed its login widget.

Separate v5 disks without Mozilla exercised the kernel and PROM boot-file
replacement in both directions. Each reboot checked the running kernel,
module, xdm and the absence of a browser receipt. For the R4400 base-only
test, the published v5 disk hash matched, but the manual bundle's NVRAM had
changed. The test used a private copy of the qualified 6.5.22f Mozilla Indy
NVRAM. An initial attempt requested a reboot while xdm was starting and
stalled in the v5 shutdown hook. The repeat waited for the visible greeter
before updating. The measurement record identifies both inputs.
