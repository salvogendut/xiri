# IP28 High IMPACT 2D display updates

On an emulated Indigo2 R10000, the native IMPACT driver now sends one hardware fill for a changed, single-colour 64×8 tile. The previous driver issued up to eight single-line fills for those pixels. Mixed tiles use the existing line transfer, with up to eight FIFO writes per status check. The original path waited for an empty FIFO between every two pixels. The new path checks for space during a line transfer and drains the FIFO at the start of each block. Text console operations still submit updates synchronously, including in DDB.

The desktop still uses Xorg's `wsfb` driver and a RAM framebuffer. These changes accelerate display updates for existing clients. Xorg continues to execute pixmap copies in software. The chip draws solid rectangles and receives the changed pixels for patterned areas.

## Visible update latency

A native Xlib client drew into a 640×480 window on the 1280×1024 display. Each number below is the median of five alternating frames, measured from the host's serial drawing request until the pixel near the bottom right changed on the emulated display. The two workloads were a solid rectangle fill and a copy from a checkerboard pixmap. Timing includes serial delivery, guest scheduling, Xorg, kernel uploads and monitor polling. The runs used separate overlays and the same IRIS binary. Some 6.5.22 measurements overlapped host CHD compression. The full-frame RGB comparisons and raw timings are in the [qualification record](2026-11-22-ip28-2d.json).

| IRIX release | 640×480 operation | Previous kernel | New kernel |
| --- | --- | ---: | ---: |
| 6.5.22 | Solid fill | 417.03 ms | 181.99 ms |
| 6.5.22 | Patterned pixmap copy | 631.02 ms | 399.96 ms |
| 6.5.30 | Solid fill | 400.06 ms | 169 ms |
| 6.5.30 | Patterned pixmap copy | 1551.92 ms | 481.8 ms |

The latency figures apply to these two 640×480 workloads. Window dragging and winterm scrolling will need their own measurements before choosing a screen-to-screen copy implementation.

## Correctness and artifacts

The scanout test compares every pixel in the final fill and checkerboard frames, 307,200 pixels per workload. The independent existing atlas and colour checks inspect another 8,944 displayed pixels per run, including an odd-width image. Keyboard and mouse input, Xorg startup and shutdown also run on the baseline and candidate. The first development capture included the X cursor over 176 pixels of the solid fill. The fixture now moves it clear before drawing.

The separate packaged CHDs boot with their saved graphical-console firmware. An outer host test process ended during the first login attempt on both disks. Both guests shut down to the PROM on request. The recorded results come from fresh overlays launched directly. Each full check covers PS/2 console login, DDB evaluation/continue, full-screen xdm, IRIX 4Dwm login, native ctwm login, IRIX relogin, and orderly return to the graphical PROM menu. The attached fixture CD for this check contains only the session test source and its checksum. The matching module resolves all 172 kernel imports. Coverage is emulated High IMPACT at 1280×1024. Physical boards and 3D require separate testing.
