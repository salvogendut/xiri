# IRIX audio controls on the Indy

SGI's desktop uses two different panels. **System & Desktop Sounds** selects
sound preferences, including the keyboard bell and key click. **Audio Panel**
owns the hardware volume sliders. NetBSD's native `mixerctl outputs.master`
provides an independent readout of the left and right speaker levels.
[SGI Desktop User's Guide](https://techpubs.jurassic.nl/library/manuals/1000/007-1342-180/sgi_html/ch11.html).

## What the vendor programs ask for

On original 6.5.22f both panels open `/dev/hdsp/hdsp0master` read/write and
read the default output from the system resource with ioctl 25. The library
uses ioctl 27 for a parameter's description and 26 to enumerate its values.
Audio Panel also looks up resources by name (28) and opens `hdsp0events` to
subscribe to changes (112). The original Indy reports analog and AES input
and output devices. Its analog output resource 6 has line-out interface 21
and headphone/speaker interface 22. The original 6.5.30f O2 donor reports
A3 hardware with different interfaces and gain ranges. Both target v6
images use Indys with HAL2. [Release-specific hardware measurements](2026-11-26-hdsp-donors.json).

A private copy of the original Indy also delivered a gain change to an
independent event handle. After subscribing to analog output and changing
its gain, libaudio's pending-count request returned one. The event identified
the active line-out interface (21), analog output (6), gain parameter
(`0x10000019`), A2 subsystem (25) and two channels. The NetBSD adapter uses
the active headphone/speaker interface (22) as its source. With two open
queues, the original driver's `poll` marked only the subscribed one
readable. Draining the event cleared readiness.

SGI's factory layout requests `DefaultOut`. Audio Panel reads the default
output's label, then asks libaudio to resolve **Analog Out** to a device.
On the original Indy, both that label and `A2.AnalogOut` resolve to the
path system → A2 → device 6. Resolving just the dotted name left the
original panel frame empty. Device 6 also identifies A2 (25) as its
containing subsystem. The next factory menu queries the output's master clock.
The original Indy reported external AES (12), 44.1 kHz crystal (13) and
48 kHz crystal (14), with 14 selected. The module reads the native hardware
format through `AUDIO_GETFORMAT` and exposes the active internal crystal
and its SGI label. The panel can read the hardware sample rate. Clock
switching is outside this update.

## The native adapter

The compatibility module translates IRIX discovery and stereo gain requests
on the native HAL2 mixer. A symlink under the IRIX device directory reaches
`/dev/audioctl0` with the caller's native permissions. The adapter exposes the
Indy's analog output and headphone/speaker control. Native `haltwo` provides
stereo playback and a single stereo master. It has no recording mixer or
independent AES or line-out controls to expose to IRIX applications.

The module also supplies a separate event queue for each open of
`hdsp0events`. It wakes an IRIX `select` waiter on a subscribed IRIX mixer
write. A boot script creates the native event node with the module's current
character major. Installing the add-on creates the two IRIX device links and the boot script. Restoring v6 removes the service and links.

The original Indy reports a speaker gain of 36.123599 dB at a default level
equivalent to 64 on the eight-bit mixer. The adapter translates between
signed 32.32 dB and eight-bit left/right gain, including silence. The test
sets different left and right levels through an n32 IRIX executable as
`xiritest` and reads both back with native `mixerctl`. PCM ring-buffer
playback and audible desktop sounds require additional interfaces.
[Source and build procedure](../../lab/irix-hdsp/README.md).

## Why the slider needs a kernel update

NetBSD starts these Indys at zero speaker gain. The SGI slider converts
digital silence to the exact 32.32 integer `-2^63` in libaudio's
`alDoubleToFixed`. In a vendor process dump, the input register contained
`0xc3e0000000000000` and the instruction was `trunc.l.d`. The R4400 and
R5000 delegate large long conversions to software. The v6 kernel handled
`cvt.d.l` in the opposite direction but delivered `SIGILL` for `trunc.l.d`.
The new kernel implements truncation in the saved floating-point context.
On the earlier kernel, changing the native mixer from zero to 64 before
launch let the SGI panel open and provided an independent check of the cause.

The NetBSD changes are [MIPS conversion 4c5351b5290](https://github.com/salvogendut/NetBSD-xiri/commit/4c5351b5290) and [HDSP 9c7a8ae5db8](https://github.com/salvogendut/NetBSD-xiri/commit/9c7a8ae5db8). Both o32 and n32 probes check 40 truncation cases and 52 integer-to-double cases per ABI, including the silence value and all four FPU rounding modes.

## Desktop checks

Both sessions logged in through xdm as `xiritest` and opened both applications
by double-clicking their ControlPanels icons. Middle-clicking each linked
slider changed the native HAL2 master from `0,0` to `185,185` and then
`26,26`. In System & Desktop Sounds, Key Click changed Xorg from 0% to
51% and back. Both original v6 boot sets were then restored, rebooted to a
visible xdm greeter and cleanly halted. The 6.5.30f rollback check resumed
on the same guest's serial console after a host runner interruption.

## Manual test on either Indy v6 disk

The native CD is shared by both release lines. Its SHA-256 is
`930c6ace8f952940f2ced991d4c79dea8a635f4f39e5e7cb56273a84552da384`. Attach it to the launcher for the release you use.

```sh
release=6.5.22f  # or 6.5.30f
.work/images/xiri-clean-indy-${release}-v6-20261126/run-iris.sh \
  --cdrom4 "$PWD/.work/installers/indy-11.99.11/hdsp-v1/indy-hdsp.iso"
```

Log out of the desktop. In the NetBSD root console, install the add-on and
reboot. It verifies the v6 hashes of `/netbsd`, `/netbsd.boot` and the original
compatibility module and keeps a `.pre-hdsp` backup of each. Enable HAL2 with `no_audio = false`
in the launcher's `iris.toml` if using an older copy of the bundle.

```sh
mkdir -p /cdrom
mount -rt cd9660 /dev/cd0a /cdrom
sh /cdrom/install.sh
shutdown -r now
```

After boot, log in as `xiritest`. The panels are under **Icon Catalog →
ControlPanels**. In **Audio Panel**, middle-click the left or right volume
track and read the linked stereo level with `mixerctl outputs.master` in
winterm. In **Sounds**, toggle **Key Click** and read `xset q`.
To roll back, mount the same disc as root, run
`sh /cdrom/install.sh --restore` and reboot.
