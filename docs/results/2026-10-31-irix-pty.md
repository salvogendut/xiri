# PTY allocator checkpoint — 2026-10-31

Original xwsh now passes PTY allocation and reaches unsupported `fork` (1002).
The original libc `_getpty` helper also allocates a native master and opens its
slave as root and uid 1234. A separate libc test then reaches unsupported
`tcgetattr` (ioctl 0x54d5). No winterm window, shell or input is qualified yet.

## Implementation

The NetBSD branch `xiri/irix-pty` extends the previous access checkpoint.
Both accepted kernels pin implementation revision `171703da4b0`; the later
README-only commit does not change those binaries:

- Decode legacy `O_NDELAY` (4) and `O_NOCTTY` (0x800); legacy nonblocking maps
  to native `O_NONBLOCK`. `F_GETFL` returns canonical 0x80 instead of preserving
  IRIX's distinct legacy bit. Empty-read legacy semantics are not emulated.
- Supply `chmod` (1015) and `chown` (1016) with explicit 32-bit arguments and
  native credential/vnode authorization. This IRIX installation permits an
  ordinary owner to give a file away; NetBSD rejects the measured giveaways
  with EPERM and preserves ownership. That native policy is retained.
- Translate `st_rdev` only for actual native master/slave PTY character
  devices with minor below 400, to IRIX majors 14/15. Other devices and
  filesystem IDs keep their existing encoding; native ownership/mode remain.
- Recognize only `I_STR` 0x5308 carrying `{0x5002,0,0,0}` on a native PTY
  master. Native unlockpt has no slave-lock operation. The adapter validates
  the descriptor/request; it does not grant ownership or alter permissions.

The disposable guest uses the native ptm clone interface and ptyfs mounted
with group 0/mode 0600. A nullfs view at `/emul/irix/dev/pts` lets absolute
slave aliases resolve inside the foreign namespace. The first 400 q/r names
are supplied as symlinks. This is a lab configuration; production namespace,
higher PTY banks, allocation beyond the repeatedly reused minor 0, concurrent
allocation and slave-lock isolation are not qualified. No original device nodes or machine account state are imported.

## Explicit compatibility policies

| Case | Original IRIX observation | Bounded native behavior |
| --- | --- | --- |
| Legacy NDELAY without NONBLOCK | `F_GETFL` retains bit 4 | Canonical bit 0x80 |
| Open with bit 0x10; SETFL with 0x10/all bits | Accepted by the reference | EINVAL; failed SETFL retains prior flags |
| Invalid access mode 3 | EINVAL | EINVAL |
| Ordinary owner gives file to uid 0 or 2345 | Success on this installation | EPERM, ownership unchanged |
| Master PTY mode | 020000 | Native 020666 |
| UNLKPT timeout 1/-1 or nonzero unused data | Success in measured cases | ENOSYS outside the exact request |
| Inner command 0x5003 / length 1 with null data | EINVAL / EFAULT | ENOSYS outside the exact request |
| Valid request on ordinary file / absent fd / bad request pointer | ENOTTY / EBADF / EFAULT | Same measured errors |

All records still compare the remaining fields exactly, including identity,
metadata, guards and the unchanged request. These policies do not suppress
unexpected results. The [comparator](../../scripts/irix-pty-records.py) expresses
them as explicit expected bytes.

## Original behavior and next boundary

The supplied original IRIX GCC 3.3 builds the private n32 test program from
our `fixture.c`. Twenty original runs cover `_getpty`, clone opens, regular
files, `/dev/null` and a FIFO across four flag combinations. Original IRIX
keeps NDELAY separate from NONBLOCK; when both are requested, NONBLOCK wins.
The installed o32 compiler attempts failed, so o32 is measured by the separate
libc-free probes. No compiler licensing workaround is used.

On NetBSD, successful `_getpty` leaves errno 89 from an ignored internal
unsupported query. The returned pointer and open slave establish success;
errno is not meaningful after a successful API call. The next `tcgetattr`
returns ENOSYS and leaves the 48-byte poisoned termios buffer untouched.

Original xwsh requests a PTY with flags 6, reads both slave names, applies
mode 0622, and successfully unlocks the native master. Unsupported signal-mask
calls (1164) surround its failing `fork`. It exits 255 with “Function not
implemented: can't start command”; the X tree stays empty. Next measure child
return registers, signal masks, native exec/session handling and terminal
attributes; then qualify shell/input/cleanup before evaluating original 4Dwm.

## Reproducibility and limits

[Lab instructions](../../lab/irix-pty/README.md) describe the paired records,
original-libc observer and native controls. Source/kernel/emulator pins are in
[baseline.json](../../lab/irix-pty/baseline.json) and
[o32-baseline.json](../../lab/irix-pty/o32-baseline.json). Both kernels were built
sequentially with at most two compiler jobs; the emulator is unchanged.

The initial fixture runs are excluded (the failed original fixture run also
did not complete a clean guest halt; its emulator was terminated). Inline
assembly omitted caller-saved clobbers, and the o32 metadata offsets were wrong. The corrected probes use
conservative clobbers, measured layout offsets and actual stat-buffer guards.
Earlier namespace attempts also remain excluded: ptyfs does not support mount
updates, and a symlink alone did not expose native `/dev/pts` inside the foreign
root. Raw evidence and original bytes remain private under ignored `.work`.

PTY allocation is a separate checkpoint from complete IRIX termios, STREAMS,
legacy nonblocking behavior, signals/process lifecycle, a working winterm,
full desktop or physical SGI validation. No new application screenshot is
claimed for this checkpoint.
