# Framed NetBSD boot console on Indigo2 High IMPACT

NetBSD now displays IP28 kernel and startup messages inside the same blue gradient and inset panel used on the Indy. The machine starts at the SGI PROM, the native kernel draws the frame when it attaches its console, and xdm takes the full 1280×1024 display. Stopping Xorg returns to the framed text console. Keyboard input and DDB use the same panel.

## Try it

From the Xiri checkout, launch the image for the IRIX release you want.

```sh
./.work/native/xiri-ip28-frame-6.5.22-20261122/run-iris.sh
./.work/native/xiri-ip28-frame-6.5.30-20261122/run-iris.sh
```

The saved PROM selects `console=g` and boots `netbsd.ip28`. Press Ctrl-P if IRIS opens paused. At xdm, use `xiritest / xiritest` for 4Dwm or `netbsdtest / netbsdtest` for NetBSD ctwm. Serial B is available on port 20230 for 6.5.22 and 20330 for 6.5.30. [Serial recovery instructions](../../lab/ip28-kernel/README.md#graphical-boot-console)

## What was checked

The maintainer also viewed the framed console in a live IRIS session with the 6.5.30 image and confirmed it looked right.

- Both release CHDs passed raw and overall CHD verification and booted from their own installed kernel and saved firmware. A read-only test CD supplied the session test source.
- The 8×16 font fits 88 columns and 42 rows inside a 704×672 panel. We compared all 837,632 pixels outside it against the original cropped artwork during kernel boot, after stopping Xorg, before and after scrolling, and in DDB. Every comparison matched.
- A marker drawn on row two moved to row one after a single newline at the bottom. Its pixels matched exactly. A temporary console login accepted emulated PS/2 input, DDB returned the value of `print/x 0x1234abcd`, and `continue` resumed the system.
- Each release completed an authenticated 4Dwm login, a native ctwm login and a second 4Dwm login. Each session occupied 1280×1024 and logged out to the greeter. Both machines halted to the graphical PROM, and the standalone base images retained their original hashes.

## Implementation and scope

NetBSD `xiri` at `22a150d9cba5ea52c6dfe4d8fea54d036f8015e0` enables the optional `IMPACT_FRAME` setting in `XIRI_IP28`. The driver reuses the rectangle and palette data generated for Newport from `xiri/graphics/sgiconsole.png`. It clips the source's two extra rightmost columns and confines console text operations to the centered grid. The full IMPACT framebuffer remains available to Xorg. The rectangle fills update scanout and the RAM copies used by the fast display path. They can run during early boot and while DDB has stopped the scheduler.

The driver also compiled with the option disabled. Runtime coverage used IRIS High IMPACT at 1280×1024 with the default bitmap font. Physical boards, other IMPACT models and alternative console fonts have separate qualification needs. The [2D transfer measurements](2026-11-22-ip28-2d.md) were taken on the preceding kernel. IRIS upstream was fetched at `ec3dcec36a6d`, already integrated in our `xiri` at `a90c5a484180`. The same emulator binary ran both releases.
