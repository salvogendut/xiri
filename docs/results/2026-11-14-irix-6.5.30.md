# Separate IRIX 6.5.30 qualification

The original-media **6.5.30f** donor is exported, verified and inventoried.
Two independent imports produce identical vendor archives and manifests.
The **O2/R10000** trial reaches native NetBSD SCSI initialization, where a
kernel trap prevents login. No 6.5.30 application has run on NetBSD yet, and
there is no qualified 6.5.30 Xiri CHD. The existing 6.5.22
reference, donor, profile and native package remain independently qualified.

## Source and payload

The [media audit](2026-11-14-irix-6.5.30-audit.json) records the Foundation CDs,
ONC3 NFS, three 6.5.30 overlays and Applications August 2006 used by the saved
Prismatic/Instigator installation. The installed O2's base, sector overlay and
dirty map are merged read-only; the empty base alone is not a donor. The
[donor record](../../lab/irix-donor/6.5.30f.json) pins all source files, the
verified CHD/raw round trip and fresh native boot evidence. Original disk files
and NVRAM are preserved.

A disposable O2 R5000/256 MB boot reports `6.5 6.5.30f`, then powers off after
`shutdown -p -g0 -y`. It uses the previously qualified `819c6825` emulator.
This is a serial boot/release/shutdown check, not a new native graphical-login
qualification. An earlier graphical-console attempt was interrupted before a
result; its orphan emulator was found through host-visible process inspection
and explicitly stopped. Its evidence is retained as interrupted.

The serial probe's initial shutdown polling deadline expired just before the
natural power-off completed. The original result is preserved alongside a
separate review: exit 0, the guest's shutdown message, the O2 power-off message
and `Machine: soft power-off` confirm completion. The maintained probe now waits
longer and checks the final process outcome too. It supports explicit
machine/release selection, serial-only O2 boot and the PROM Start System action.

## CPU requirement and NetBSD trial

The [ELF header inventory](../../lab/irix-donor/6.5.30f-isa.json) finds 181
MIPS III, 66 MIPS II and 14 MIPS IV files. The MIPS IV set includes n32 libc,
libm and O2 graphics libraries. This requires a MIPS IV CPU; the selected
trial is **O2/R10000**, retaining the R4400 reference for 6.5.22. An ELF declaration is not exhaustive instruction
coverage or proof that every optional application works.

The first R4400 trial reached NetBSD but was deliberately interrupted before
vendor replacement when this CPU requirement was established. It halted cleanly
and preserved the source CHD. The R5000 trial then stopped in native kernel
initialization with `panic: r5k picache line size 16`; no 6.5.30 application had
run. Its panic PNG, exact probe and logs are retained.

NetBSD's R5000 cache initialization requires 32-byte primary lines. The local
NEC VR5000 manual, section 6.5.8 (printed pages 129–131), describes Config IB/DB
as fixed/read-only. IRIS initializes those fields to 32 bytes, but its shared
Config write path permitted software to clear them. IRIS `xiri` commit
`7d46498bf1fbf3acf53f1619413e3c5eaeb5d27b` preserves these read-only fields for
R5000 while retaining writable K0 and the older R4400 behavior. The new MTC0
executor regression failed before the change and passes afterward, as do all
190 CPU executor tests and the optimized CLI build. The commit is pushed.
The R5000 native boot has not been rerun after this correction; the user chose
the O2/R10000 trial instead.

## O2/R10000 native platform

The Indy IP2x kernel cannot be reused as an O2 IP32 kernel. The separate
[O2 configuration](../../lab/irix-o2/XIRI_O2) includes `GENERIC64_IP3x`, modular
IRIX support and an `sd0a` root. The matching module and
[native package profile](../../profiles/netbsd-sgimips-o2-native-v1.json)
use the stock native `crime` Xorg driver and `ip3xboot`. The previous Indy
kernel, module, Newport driver and manual CHD remain pinned independently.

The initial O2 R10000/256 MB boot reaches CRIME framebuffer initialization,
then faults in `r10k_sdcache_wb_range`. The backtrace is
`crmfb_attach` → `_bus_dmamap_sync` → `r10k_sdcache_wb_range`.
NetBSD's secondary-cache alignment macros complement an unsigned 32-bit line
size before combining it with a 64-bit kernel address. The compiled routine
therefore clears the address's upper half. The correction widens the line
size to `register_t` before complementing it. A test using the actual source
macros fails for 64-bit addresses before the change, then passes 32-bit and
64-bit address cases, including KSEG0 and XKPHYS, with 64/128-byte cache lines.
The corrected kernel build passes. Its cold boot passes framebuffer
initialization and reaches `ahc0` (Adaptec AIC-7880), then stops with a native
reserved-instruction trap at `memset+0x4c`, EPC `0xffffffff8064bacc`. The linked
instruction there is `sd a3,0(v1)`; the cause of this second trap is unresolved.
The cache-width correction is committed on NetBSD `xiri` as
`2a7184ec4c66b324c8c027b577a81c1e41575504`. The trial was built immediately
before that commit, with its exact source patch retained. This is a native
O2/N64 boot blocker, before vendor installation or module loading. Upstream
IRIS's NetBSD/O2 support statement does not independently qualify this new
64-bit Xiri kernel.

The [machine-readable result](2026-11-14-irix-6.5.30.json) pins the builds,
regressions, failures and retained evidence. All 83 repository host tests pass.
The unsuccessful guests never mounted their root writable; their emulators
were stopped, and both the original native CHD and donor flash hashes remain
unchanged. The retained O2 package is a build candidate, not guest-qualified.

The preparation fixture uses a private CHD overlay and private O2 flash,
verifies native and vendor packages, installs matching kernel/module and
`ip3xboot`, selects O2 Ethernet/serial devices and records its result. It is
not the clean-target installer. A prepared disk still needs a graphical cold
boot and desktop/session checks before becoming a manual-test image.
The O2 PROM uses `>`, and the single-user TFTP command is
`boot -f bootp():netbsd-XIRI_O2 --s` (the PROM removes one leading dash).

## Reproduction

```sh
./xiri import \
  --profile profiles/irix-6.5.30f-v1.json \
  --source .work/donors/irix-6.5.30f-original-media/irix-donor.chd \
  --output .work/imports/irix-6.5.30f-v1
```

The output directory must be new. Keep 6.5.22 and 6.5.30 sources, payloads,
qualification evidence and test CHDs separate. Do not select a new manual CHD
until its cold boot and desktop checks pass.

See the [O2 lab](../../lab/irix-o2/README.md) for the exact native build and
boot fixture. The next bounded task is the O2/N64 SCSI-stage trap. Desktop
and session checks follow only after native login works.

The subsequent [Octane/R10000 trial](2026-11-14-octane-platform.md) confirms
that changing to Octane does not bypass native platform work: its firmware
rejects the ELF32 wrapper, the ELF64 kernel faults during loading, and the
NetBSD tree lacks the required Octane board attachments. A smaller alternate
experiment is to retry the existing Indy/R5000 kernel with the tested IRIS
Config correction; that native boot remains untested after the fix.

Cleanup retained compact failure records, source/tests, the kernel/module and
debug symbols, both donors/payloads and the selected 6.5.22 image. It removed
failed guest copies and temporary Rust/NetBSD build output: 6.67 GiB of file
allocation, with available filesystem space increasing by 4.71 GiB (reflinks
share some blocks). All test IRIS processes are stopped.
