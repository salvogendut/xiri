# Vendor o32 and n32 execution on LP64 — 2026-10-30

The LP64 NetBSD kernel now runs unmodified IRIX 6.5.22m o32 `asa` and n32
`echo` through their original libc and rld. Exact output, empty stderr and
zero exit status are required as root and UID 1234/GID 5678. This extends the
successful o32 path to n32 and preserves the separate 32-bit kernel route.
It does not establish general IRIX application or desktop compatibility.

The [lab](../../lab/irix-lp64/README.md) contains reproduction commands,
configs and input pins. The [JSON record](2026-10-30-irix-lp64.json) retains
final observations, source/artifact hashes and regression summaries. Vendor
binaries, firmware and disks remain private ignored inputs.

The opt-in personality retains its historical `COMPAT_IRIX_O32` option name.
Its foreign argument structures now use explicit 32-bit types. Pointer
widening, unsigned sizes and signed 32-bit file offsets are distinct. o32
uses four register slots and checked 32-bit stack spills; n32 uses eight
register slots. An indirect selector consumes the first slot. The current
allowlist has at most six arguments and only 32-bit argument/return types;
there is no n32 stack spill or foreign wide-offset syscall claim. Saved
64-bit GPRs and n32 odd floating-point registers survive tested traps.

ELF acceptance distinguishes o32 and n32 and rejects mixed executable/libc
ABIs. n32 dynamic flags are 0x20000024 for the main executable and 0x20000022
for the interpreter; the accepted paths are `/lib32/libc.so.1` and
`/usr/lib32/libc.so.1`. MIPS III is required for n32. Process ABI state changes
only after executable selection succeeds. LP64 uses netbsd32 argument copying
and address placement, with 32-bit argc, argv, envp and auxiliary entries.

An initial implementation used the LP64 default definition of `elf_args`.
The ELF32 loader actually supplies a 20-byte object, so reading native-width
fields corrupted auxiliary data and caused both vendor runtimes to fault.
The synthetic interpreter caught the bad auxiliary vector. Explicit
`ELFSIZE=32`, guarded by layout assertions, fixed that boundary and restored
asa. Both synthetic interpreters now check every auxiliary entry, argument
layout, initialized data and BSS before entering the program.

The bounded linked-address loader requires alignment to the running kernel's
page size. All four supplied libc/rld files and both vendor programs have
suitable load alignment. Separate malformed fixtures contain otherwise
plausible 4 KiB-only segment boundaries and must fail exec with ENOEXEC.
The kernel reports its real 8192-byte page size to both foreign ABIs. It does
not emulate arbitrary IRIX 4 KiB mappings on an 8 KiB VM system.

## Heap growth and vendor echo

After loading worked, echo reached its original libc but printed
`echo: Function not implemented` for nonempty argument lists. Its trace
identified `break` (1017), requested while allocating its output buffer.
Empty-argument echo had already printed a newline, so that case alone would
have missed the missing operation. Successful startup now records 26 calls,
including one break request for 0x10008000; asa retains its 24-call path.

The new wrapper converts the foreign pointer and calls native `sys_obreak`.
It rejects addresses below the data-segment base or beyond the bounded
32-bit user range before page rounding. Native VM operations enforce the
data limit, refuse growth over occupied mappings, supply zero-filled private
pages and release pages on shrinking. Success returns zero explicitly.
This prevents native data-size underflow on a below-base request. It does
not promise IRIX executable heap or shared-process behavior.

Original fixtures cover both ABIs and direct/indirect calls: unaligned
growth, preserved data, shrinking, zero-fill after regrowth, a fault on a
released page, collision preservation, the 16 MiB data limit, and null,
below-base, high and wrapping requests. The native parent captures default
SIGSEGV separately from exec failures and exit codes.

Asa exercises seven carriage-control inputs, including empty and
unterminated input. Echo exercises no arguments, one argument, two arguments,
an argument containing spaces, an empty argument and an empty middle
argument. Every input is compared with the original IRIX installation.
These are bounded command paths, not complete coverage of either utility.

## Original IRIX comparison and limits

The original reference reports 4096-byte pages; the LP64 kernel reports 8192.
Unknown sysmp commands and indirect selectors return EINVAL on the reference
and the explicit ENOSYS policy on Xiri. The tested syscall-in-delay-slot and
nested-indirect probes terminate with SIGSYS on IRIX; Xiri handles delay-slot
return and rejects nested dispatch with an error.

Heap growth, regrowth zero-fill, collision preservation, data-limit failure,
high/wrapping rejection and released-page faults agree for these probes.
Null and below-data requests terminate the reference probes with SIGSEGV
when they subsequently access initialized data; Xiri rejects the requests
with ENOMEM and preserves that data. This is an intentional bounded policy,
not a claim of identical destructive shrinking semantics.

The reference pin records exact measured behavior, including differences;
map addresses are normalized only where native placement may legitimately
vary. Its disk content hash was established during intake; each run checks
size and validates uploaded fixtures and runtime files inside the guest.
The reference uses the previously qualified default emulator, whose hash is
recorded separately from the NetBSD LP64 emulator.

Unsupported runtime queries still return explicit errors. No foreign signal
handlers, PRDA, shared address spaces, thread creation, n64 applications,
general relocation, broad library loading, desktop services or hardware
qualification are established here. Native wide syscall tests do not qualify
foreign wide syscalls. Reference XFS alerts and a clean graphical reference
session remain open.

The next step is to inventory the transitive libraries, resources and
services required by the supplied n32 4Dwm and Toolchest, then capture their
first reproducible startup boundary on this kernel. Add only the behavior
identified by that evidence, with original-IRIX comparisons. Desktop success
still requires the real session, application launch, input and repeated
logout/login checks in the roadmap.
