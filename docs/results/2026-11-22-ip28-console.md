# IP28 graphical boot and debugger console

This checkpoint adds native IMPACT console output before Xorg starts. The
separate IRIX 6.5.22 and 6.5.30 images keep serial B for administration and use
`console=g` for the local display. The loader first uses the graphical ARCS
console; NetBSD then owns text output, followed by native Xorg/xdm at
1280×1024.

Qualification and artifact hashes are recorded in the [result JSON](2026-11-22-ip28-console.json).
The earlier [serial-console xdm images](2026-11-22-ip28-xdm.md) are retained.

## Implementation

NetBSD changes are on the fork's `xiri` integration branch at
`b2c431a3b18f9fd3aded411e92bd020e463a4a90`:

- `gio.c`, `files.gio` and `impactvar.h` expose the IP28 IMPACT early console
  probe without changing the normal GIO product-ID attachment.
- `impact.c` uses a page-aligned 5 MiB static framebuffer before UVM is ready.
  Early rasops initialization uses `RI_NO_AUTO` to avoid dynamic glyph
  allocation, and `wsdisplay_preattach` allows the later genfb handover.
- Text operations update RAM and upload the affected rectangle synchronously.
  Normal mapped Xorg writes still use the existing framebuffer update thread.
  Transfers use even spans of up to 64 pixels, preserving odd glyph edges.
- Each FIFO transaction runs at `splhigh` on this uniprocessor platform.
  Keyboard debugger entry cannot interrupt a command packet. Polling stops
  background uploads, redraws the console and supports text output without
  scheduling. FIFO failures remain bounded and are latched to avoid recursive
  console-error printing.
- `genfb.c`/`genfbvar.h` add one optional backend screen-initialization callback
  before vcons saves the text operations. IMPACT uses it to wrap rasops,
  including after font initialization. Existing backends zero-initialize their
  operation tables and do not use this hook. No new userspace ioctl, Xorg
  driver or IRIX-personality hook is needed.

The native wscons configuration no longer explicitly allocates screen 0:
`console=g` supplies it in the kernel. `prepare-console.sh` installs a matching
kernel/module pair and preserves the existing users, xdm sessions and serial
getty. The module remains loadable at boot; it is not compiled into the core.

## Qualification

The visible checks cover early text, normal device attachment, startup
services, PS/2 console login, DDB entry/evaluation/continue, and handover to
xdm. The existing full session probe checks `xiritest` with IRIX 4Dwm/winterm,
`netbsdtest` with native ctwm/UXTerm, logout and IRIX relogin, full-screen Xorg,
authorization isolation, stable system services and orderly shutdown.

Both release lines pass the full console/session sequence: 384.96 seconds
for 6.5.22 and 394.18 seconds for 6.5.30. These are qualification durations,
not display benchmarks. The matching module audit resolves all 172 imports,
checks full-width MIPS relocations and finds no built-in IRIX personality.
The final kernel also passes serial boot/shutdown in both release lines.

Graphical shutdown no longer prints the PROM menu on serial B. The probe
requires three successive samples executing in PROM ROM and retains a PNG of
the returned maintenance menu. Packaged images receive a separate automatic
cold-boot check without fixture media. The original base CHD hashes are checked
before and after each run.

Both standalone CHDs pass verification and their separate cold boots. The
firmware seeds are used unchanged, with no PROM commands or test CD required;
each image reaches full-screen xdm and returns to the graphical PROM menu on
shutdown. The previous serial-console images remain available for comparison.

Development caught and corrected missing early GIO probing, an attempted
pre-UVM glyph allocation, and the need for `wsdisplay_preattach` at the early
stage. The temporary getty test also disables shell job control so `login_tty`
can create its own session, waits for the `-sh` login process, and checks
the debugger value after its prompt. Image preparation preserves `xdm_flags`
when enabling xdm, so Xorg receives the existing Xiri configuration. These
failed candidates are not published as test images. One later 6.5.22 run
ended with IRIS reporting a soft power-off during login; its bounded repeat
passed the complete sequence. No emulator fix is claimed for that interruption.

## Manual test and recovery

The new bundles are separate from the previous checkpoints:

```sh
./.work/native/xiri-ip28-console-6.5.22-20261122/run-iris.sh
./.work/native/xiri-ip28-console-6.5.30-20261122/run-iris.sh
```

Run one launcher for the desired vendor release. Press Ctrl-P if IRIS starts
paused. Boot text appears locally before the xdm greeter. The existing public
test accounts remain `xiritest / xiritest` for IRIX and
`netbsdtest / netbsdtest` for native NetBSD. Serial B is port 19830 for 6.5.22
and 19930 for 6.5.30; root has no password in these disposable images.

Use `shutdown -h now` before closing IRIS and wait for the graphical PROM menu.
For recovery, select `console=d` in the PROM and reset. In serial-console mode,
run `wsconscfg 0` before starting xdm if a graphical screen is needed. Return to
`console=g` for normal graphical boot. Detailed build/test steps are in the
[lab guide](../../lab/ip28-kernel/README.md#graphical-boot-console).

## IRIS upstream and limits

Upstream was checked at `ec3dcec36a6d561aca8b306d2f95cd49d5a65eaf` and merged
into IRIS `xiri` as `a90c5a484180c41c41098fcb38ee964e4346baad`. Its change
excludes a plain-thread test helper from loom builds. The affected JIT flush
regression passes, as do all nine loom models. The retained emulator binary
from `0bc52567` has equivalent production code; the subsequent changes are
confined to tests/documentation.

Coverage remains emulated IP28/R10000, 1 GiB RAM and High IMPACT at 1280×1024.
Physical cache/DMA behavior, other board variants/display timings, DMA/3D and
broader display acceleration remain separate work. This does not qualify every
DDB command or debugger entry while Xorg is drawing. The generic genfb hook
has source-level initialization review, not runtime coverage on other ports.
The inherited `savecore` namelist warning remains: these images boot
`netbsd.ip28` while `/netbsd` still names the earlier kernel. Crash-dump
configuration is outside this console checkpoint.

## Next IMPACT work

Prioritize 2D display performance before the decorative frame. Xorg currently
renders through generic `wsfb` into RAM; the kernel uploads changed spans.
Uniform spans already use a hardware fill, but this is not Xorg 2D
acceleration. Measure drawing/scrolling and transfer costs, then add hardware
fills/copies and a faster upload path while retaining the qualified fallback.
Validate both vendor releases after each shared display change.

The Indy's decorated console is implemented in the Newport driver's
`NEWPORT_FRAME`/`NEWPORT_DECOR` path. IMPACT does not inherit those hooks.
Reuse the existing artwork/layout through the shared console-decoration
support, with explicit drawing and scrolling integration for IMPACT. Preserve
early text, debugger readability and transitions to/from Xorg.
