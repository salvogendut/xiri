# O2 graphical login and desktop response

The O2 images use NetBSD's bitmap Spleen font for xdm. The welcome message, username, login and password prompts render on the CRIME display. Xorg still uses the accelerated `crime` driver for the 4Dwm and ctwm sessions. [Screenshot with the username and password prompt](2026-11-23-o2-xdm-password.png)

| Desktop release | Run from the Xiri checkout | Serial console |
| --- | --- | --- |
| 6.5.22 | `./.work/native/xiri-o2-greeter-6.5.22-20261123/run-iris.sh` | `telnet localhost 20843` |
| 6.5.30 | `./.work/native/xiri-o2-greeter-6.5.30-20261123/run-iris.sh` | `telnet localhost 20851` |

Boot messages go to serial. Log in as `xiritest` for 4Dwm or `netbsdtest` for ctwm. Each test account's password is its username. Each launcher creates its own writable overlay.

## What changed

The original greeter painted black rectangles across the full text bounds. We captured those rectangles, blank labels, and the effects of changing Xft antialiasing, face settings and XAA options on a private 6.5.30 disk. We then built xdm's own core-font widget from the NetBSD 11 X sources. The O2-specific library links this widget with the original sgimips `greet.o` and `verify.o` from the release's `libXdmGreet.a`. It uses the stock NetBSD xdm resources and PAM configuration. Only the O2 disk selects the library through `DisplayManager.greeterLib`. [NetBSD login widget source](https://github.com/NetBSD/xsrc/blob/b3e9d7e64782fe61c36450dae1c24116598fef89/external/mit/xdm/dist/greeter/Login.c) · [Build script](../../lab/irix-o2/build-greeter.sh) · [Guest installation script](../../lab/irix-o2/install-greeter.sh)

The cold-boot check compares the bitmap letter shapes for “Welcome to xiri-indy”, “Login”, the typed `xiritest` and “Password” against a verified capture. It also submits an invalid login, checks the visible rejection, and exercises both desktop logins and logout to xdm. [Rejection message](2026-11-23-o2-xdm-rejected.png) · [Disk hashes and results](2026-11-23-o2-greeter.json)

Run the check on either release with a fresh output directory.

```sh
IRIS_NO_IDLE=1 python3 lab/irix-o2/check-disk.py --check-greeter \
  --bundle .work/native/xiri-o2-greeter-6.5.30-20261123 \
  --emulator .work/emulators/iris-ip30-jit-08e53ba7 --output .work/o2-greeter-recheck
```

## Updating an existing O2 overlay

To keep an existing desktop and its preferences, attach the local update ISO as a CD-ROM at SCSI ID 4. In the original O2 bundle's `iris.toml`, the path is relative to the bundle.

```toml
[scsi.4]
cdrom = true
path = "../xiri-o2-greeter-update-20261123/o2-xdm-update.iso"
```

Boot that bundle. With the desktop logged out, run the commands below as root on its serial console. The ISO contains the same login widget used by the new CHDs.

```sh
mount -r -t cd9660 /dev/cd0a /cdrom
sh /cdrom/install-greeter.sh /cdrom/libXiriO2Greet.so
umount /cdrom
/etc/rc.d/xdm restart
```

To rebuild the library, use the sgimips NetBSD 11.0 X development set and chip-independent xdm sources at `b3e9d7e64782`. Run `sh lab/irix-o2/build-greeter.sh /path/to/xdm/dist libXiriO2Greet.so`. For a cross-build, set `CC` to the absolute path of the sgimips o32 cross-compiler, `NETBSD_SYSROOT` to the NetBSD C sysroot and `X11_PREFIX` to the extracted target `usr/X11R7` directory containing the X headers and libraries.

## Desktop response

We timed seven alternating clicks on each window's exposed title bar after warm-up using IRIS `08e53ba7` with the R10000 JIT. Timing starts at button-down and ends when a fresh 304×40 screen capture shows the raised window over at least 99% of the overlap. Each O2 guest ran separately. These measurements used the first O2 disk pair, before changing the greeter.

| IRIX release | Cold boot to captured xdm | Raise File Manager | Raise winterm |
| --- | ---: | ---: | ---: |
| 6.5.22 | 51 s | 142 ms | 141 ms |
| 6.5.30 | 53 s | 141 ms | 142 ms |

The earlier Octane JIT measurements ranged from 212 to 289 ms on this workload. The O2's monitor round trips contribute substantially to the reported times. On 6.5.22, enabling immediate TCP acknowledgements on the sampling connection gave medians of 18 ms for File Manager and 33 ms for winterm. The Indy tests timed dragging and scrolling, so a direct Indy comparison still needs the same window-raise test.
