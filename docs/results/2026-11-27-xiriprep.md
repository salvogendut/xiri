# On-target IRIX donor and account preparation

The XiriBSD Indy tools CD has SHA256
`76ea6b7ed75e1df052a44dfe05831840922d01413c395243fa2244528e55268d`.
The native MIPS reader has SHA256
`a59bfdbbffbdb95b51da1309dcb9a254df0480783a933ae8f9f90db2be399315`.
A second cross-build in the Fedora Toolbox fetched the pinned libchdr
revision `93d8c239` and reproduced that executable. [Using the tools CD](../XIRIPREP.md)

## External media

The two prepared Indy systems ran the reader from their native NetBSD
userland. Each mounted two data CDs and a second FFS disk read-only.
The CDs contained the reference CHDs, both named `Donor backup.data`.
The disk held the corresponding 4 GiB and 8 GiB raw images as regular files.
Both raw file hashes matched the recorded whole-disk exports.

| Donor | CHD on CD | Raw file on second disk |
| --- | --- | --- |
| IRIX 6.5.22f | Shell and 4Dwm matched 6.5.22f | Same fingerprints |
| IRIX 6.5.30f | Shell and 4Dwm matched 6.5.30f | Same fingerprints |

Neither reference image passes the fork’s clean-journal mount check. The
6.5.22f journal reports that recovery is needed, and the 6.5.30f journal
header or checksum is unsupported. Fingerprinting reads the on-disk XFS
metadata and emits a digest. For an export with an expected SHA256, the
reader stages one file and releases its bytes only after a match. The
guest exported the IRIX shell from each CD and verified the result against
the release profile. Supplying a wrong hash produced a failure and zero
output bytes. Unrestricted file export requires a clean journal.
[Repeat the guest media checks](../../lab/native-iso/check-xiriprep.sh)

## NetBSD accounts

The 6.5.22f R4400 and the 6.5.30f R5000 prepared systems both passed the
following checks in IRIS.

- A non-root caller was refused. Selecting root as the desktop user was
  also refused.
- Checking a missing user, running without a terminal and declining the
  prompt left the account absent. Accepting it created a NetBSD account
  with a password and a private `/usr/people/<login>` home.
- A pre-existing account kept its `/home` directory. The matching
  installed desktop was selected in both users’ homes with the correct
  ownership. A repeat preserved the original session backup. A third
  account retained its session selection.
- A mismatched donor release was rejected before creating a user.

On a subsequent graphical boot of each prepared system, the newly created
account logged in through xdm. Its 4Dwm session opened Toolchest and Icon
Catalog at 1280×1024. [IRIX 6.5.22f screenshot](2026-11-27-xiriprep-22.png) ·
[IRIX 6.5.30f screenshot](2026-11-27-xiriprep-30.png).

The workstation also assembled an install-set test ISO from the previously
qualified NetBSD release files and the new native tools. Readback checked
every packaged program, signature file, the source archive and their modes.

A third Indy installed all 15 sets from the original native ISO on a blank
6 GiB disk, then loaded the tools from the add-on CD. Both CHDs and both
raw files passed identification there. Account creation and existing-home
reuse passed. With no shared IRIX runtime installed, the existing user's
session file kept its original contents and the new account kept native
desktop selection. Installing the shared desktop directly from the donor
is the next milestone.
