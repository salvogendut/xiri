# IP28 Xiri module and IMPACT/Xorg, 2026-11-22

The IP28 kernel now loads the existing IRIX compatibility module and drives
native Xorg through High IMPACT. Both 6.5.22 and 6.5.30 image lines pass the
module lifecycle, native rendering and PS/2 input checks. The displayed output
matches all 8,944 reference pixels in an independent PNG check, including the
complete final colour-gradient atlas. Both imported desktops also pass winterm
shell/home/UID checks, supervised logout and clean halt.

This follows the [native serial-platform checkpoint](2026-11-22-ip28-kernel.md).
The original Indy release images and native IP28 serial images remain separate.
The [fixture guide](../../lab/ip28-kernel/README.md) gives build and test commands.

## Implementation

`XIRI_IP28` includes the native `GENERIC64_IP28` configuration, enables
`MODULAR`, selects `sd0a`, and adds IMPACT `wsdisplay` plus PS/2 keyboard and
mouse. The personality remains `compat_irix_o32.kmod`; no IRIX implementation
is compiled into the core. Its existing full-width MIPS64 relocations and long
calls work with the kernel linked at `0xa800000020080000`. All 172 module
imports resolve, and the generated relocation types are supported by the
existing MIPS module loader. No compatibility syscall or core hook changed.

The native display changes are `sys/arch/sgimips/gio/impact.c`,
`impactreg.h`, `files.gio`, and the IP28 graphics-slot entry in `gio.c`.
Hardware initialization and register definitions derive from the public
[OpenBSD driver](https://github.com/openbsd/src/tree/1228c36969f6da3d9ebfa17c7e30fa9ba94ade0d/sys/arch/sgi/dev),
with its permissive copyright/license notices retained. The local reference
is `../sgi/impact/originals/openbsd/`. No proprietary SGI source is imported.

IMPACT has no directly mapped linear framebuffer. The new driver supplies
`genfb` with a 5 MiB, 1280×1024 RAM framebuffer containing 32-bit XRGB pixels,
plus a 5 MiB copy of the last submitted contents.
A single kernel thread compares 64-pixel spans with the last submitted image,
then sends changes through the HQ3 command FIFO. Uniform spans use rectangle
fills; other spans use full-colour programmed pixel transfers. The shadow is
copied before submission so a later user write remains dirty. FIFO waits are
bounded, and a timeout reports an error and stops the worker rather than
hanging the kernel. The mmap path exposes only the allocated framebuffer.

Xorg uses the existing `wsfb` driver and software cursor. There is no new MI
wsdisplay ioctl, Xorg driver fork, emulator production change, or vendor
binary patch. This is an initial unaccelerated Xorg path; it does not expose
IMPACT DMA, hardware copy acceleration or OpenGL to clients.

## Qualification

Environment: IRIS Indigo2/IP28, R10000, banks `[512,512,0,0]`, High IMPACT,
embedded firmware and Vulkan raster backend. Serial B remains the boot/debug
console. Firmware supplies the 1280×1024 timing. Builds use the existing
NetBSD GCC 14.4.0 cross-tools, isolated source/output and at most two jobs.

The tests cover:

- Native FFS reads/writes, process execution, timers and Ethernet.
- Rejected foreign exec without the module, exact o32 fixture output after
  loading, each image's installed IRIX shell/echo, busy-unload `EBUSY`, idle
  unload, rejected exec again, and reload.
- Framebuffer dimensions, first/last mapped pixels, negative and out-of-range
  offsets; native Xorg at 1280×1024 with depth 24 and 32-bit storage.
- Xlib fills, raster operations, masks, overlapping copies, image uploads,
  odd widths and 2048/2051-wide source atlases. XGetImage verifies the software
  result; the separate PNG check verifies the displayed hardware result.
- PS/2 typing with key releases, pointer motion, all three button pairs,
  and clean termination of the native X server.
- 4Dwm, Toolchest, Icon Catalog, background icons, xclock and winterm on
  the native server, using the existing image's font/resource configuration.
  Commands typed into winterm report `/usr/people/xiritest` and UID `1234`.
  The root service launcher supervises the unprivileged `xiritest` session;
  logout stops Xorg, followed by filesystem unmount and the PROM menu.

The common o32 `asa` fixture is from 6.5.22 and uses each guest's own imported
interpreter/libraries. The shell and echo tests use the installed vendor
programs from the corresponding release line. The image's Xorg allocates
`0xfe` primary-colour components, matching the earlier Newport probe.

Single-user boot skips normal network, mount and temporary-state startup.
The desktop fixture configures loopback and the hostname, mounts the image's
filesystems and clears the inherited PTY readiness marker before services start.
This did not require an RPC or IRIX compatibility change. The typing fixture
waits for winterm's native shell handoff and tolerates a child window disappearing
during the recursive window search. It assigns keyboard focus after the window
manager has processed raise/pointer events, avoiding input going to a different
client during restored-session startup.

The native module/Xorg phases of `qualify-6.5.22` and `qualify-6.5.30` passed;
those combined runs failed in the subsequent desktop phase before the loopback
precondition was corrected. The separate final desktop runs are
`desktop-6.5.22-r6` and `desktop-6.5.30-r3`, both passing with the same final
kernel/module pair. This distinction is preserved in the
[machine-readable record](2026-11-22-ip28-impact.json).

## Manual test images

Each bundle has a standalone CHD, saved PROM settings, launcher and serial
instructions; no TFTP or qualification CD is required:

- `.work/native/xiri-ip28-impact-6.5.22-20261122/run-iris.sh`
- `.work/native/xiri-ip28-impact-6.5.30-20261122/run-iris.sh`

Launch one, connect to serial B (`19430` for 6.5.22, `19530` for 6.5.30),
choose PROM option 5 and enter `boot`. Press Return for the root shell, then:

```sh
/usr/local/sbin/xiri-ip28-desktop
```

Toolchest logout returns to that shell. Use `/sbin/halt` and wait for the PROM
menu before closing IRIS. Each launch uses its bundle's private CHD overlay.
Boot/debug messages remain on serial B; the desktop occupies 1280×1024.
Normal xdm startup is not yet qualified on this machine.

Both standalone CHDs pass `chdman verify` and a fresh disk boot using their
saved firmware settings without issuing `setenv`. The cold checks verify the
installed kernel/module hashes, IRIX shell execution, native I/O and clean
halt. Per-bundle `qualification.json` files record their separate provenance.

## Limits and next work

Initial coverage is the emulated High IMPACT board in the firmware's
1280×1024 mode. Other modes, Solid/Maximum IMPACT, Octane/HQ4, physical
R10000 cache/DMA behavior, accelerated copies/3D and a graphical early/debug
console are separate work. A polling shadow has a refresh/CPU cost; this
checkpoint establishes a usable native display interface before optimizing it.
