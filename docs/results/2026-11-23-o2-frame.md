# Framed boot console on the O2/R10000

The O2 PROM selects the graphics console with `setenv console g`. When NetBSD attaches `crmfb0`, it draws the same blue surround and inset panel as the Indy, replays the early kernel messages and displays the rest of startup there. The 1280×1024 xdm greeter then takes over. The first serial port remains available for a recovery login once NetBSD reaches multiuser mode.

## Driver and checks

The NetBSD fork's `XIRI_IP32_DESKTOP` configuration enables `CRMFB_FRAME` and the VT220 8×16 bitmap font. At 1280×1024 the graphical console uses 32-bit CRIME fills to paint the original artwork and confines terminal operations to an 88×42 cell grid. Kernel text uses the same light foreground as the other framed consoles. Xorg keeps the entire framebuffer and its accelerated `crime` driver. Selecting serial in the PROM still follows NetBSD's ordinary serial-console path. The legacy O2 kernel configuration also builds with the frame disabled. [NetBSD driver and kernel configuration](https://github.com/salvogendut/NetBSD-xiri/commit/298f35fa454)

The cold-boot check reads `root on sd0a` and `Starting root file system check:` from the actual graphical scanout, compares all 837,632 border pixels with the Indy artwork, and checks the kernel lettering. It exercises xdm, both desktop logins, logout, return to the framed console, a one-line scroll and return to the graphical PROM on shutdown. It cold-boots the same test overlay again and reads NetBSD’s clean-root check from the screen. The runs use the IRIS O2/R10000 with 256 MiB. Physical hardware requires separate testing. [Results and disk hashes](2026-11-23-o2-frame.json)

## Reproducing the update

Build the NetBSD fork's `sys/arch/sgimips/conf/XIRI_IP32_DESKTOP` using the sgimips mips64eb toolchain, and build `compat_irix_o32.kmod` from the same checkout. Stage `netbsd`, `netbsd.elf32` as `netbsd.boot`, the module and `install-frame.sh` at the root of a Rock Ridge ISO with their NetBSD-format `SHA256` manifest. The previous O2 greeter disks already contain `ip3xboot` in their volume header and have a getty on `ttyC0`. [O2 build instructions](../../lab/irix-o2/README.md) · [Guest installer](../../lab/irix-o2/install-frame.sh)

For each release, boot a private copy of its greeter disk and firmware with the ISO at SCSI ID 4. As root, mount it with `mount -r -t cd9660 /dev/cd0a /cdrom`, run `sh /cdrom/install-frame.sh`, unmount it and shut down with `shutdown -h now`. At the PROM, select **5. Enter Command Monitor**, enter `setenv console g`, and save the resulting flash when closing IRIS. Flatten the stopped disk overlay with `chdman copy -i netbsd-xiri.chd.diff.chd -ip netbsd-xiri.chd -o new.chd -c zlib`, then run `chdman verify -i new.chd`.

Recheck either standalone bundle on a fresh overlay. The matching kernel is retained with the local update ISO in `.work/native/xiri-o2-frame-update-20261123/`.

```sh
IRIS_NO_IDLE=1 python3 lab/irix-o2/check-disk.py --check-greeter \
  --frame-kernel .work/native/xiri-o2-frame-update-20261123/netbsd \
  --bundle .work/native/xiri-o2-frame-6.5.30-20261123 \
  --emulator .work/emulators/iris-ip30-jit-08e53ba7 --output .work/o2-frame-recheck
```

IRIS upstream `a05289ef` was already integrated in the tested fork revision `08e53ba7`. Both release checks used that emulator build.
