## What changed

NetBSD `xiri` commit `7b7794b0c07f31f953c34b6be6826156898649d7` fixes
`sigaction` registration for full action masks. GIMP calls `sigfillset`
before registering signal 1. The old adapter rejected its mask with IRIX
errno 122 (`EOPNOTSUPP`). The revised adapter projects the mask onto the
supported traditional signals 1..31, as `sigprocmask` already does.
It preserves an explicitly requested self-mask with NODEFER: native
NetBSD otherwise removes that signal even when the caller included it.
Foreign flag metadata is retained for subsequent queries.

This does not add checkpoint/realtime delivery. Registration for signals
32..64 and unsupported NOCLDWAIT remain rejected; queries expose the
effective mapped mask rather than original IRIX's wider mask retention.

The module SHA-256 is
`1f7beada69c483ccdf6f118e5b9bae6210b4cddfe5319f4527fb2b2cf2be4efd`.
The [build record](../../lab/irix-gimp/build.json) preserves the actual dirty
parent used to compile it and the byte-verified equivalent commit. The
qualified N64 core kernel remains unchanged at source revision
`9390bc04900a0d04796d494aca5b00651f12954d`.

The [resource ledger](../../lab/irix-gimp/resources.json) records 1,133 files,
53 directories and 31 links, including original/applied modes and checksums.
ELF files use the existing 0555 import policy. Original executable, library
and script bytes are unchanged. The earlier `/bin/sh` import has identical
shell bytes, but did not satisfy libc's `/sbin/sh` lookup.

The original setup script then invokes native `cp`. Native programs do not
apply the foreign emulation-root lookup to their pathname arguments, so the
runtime installer now creates `/usr/freeware -> /emul/irix/usr/freeware`
when the native prefix is unused. Administrator directories and links are
preserved. Setup generates `.gimp-1.2` under `/usr/people/xiritest` as UID/GID
1234. No source-image user configuration or installation database is copied.

The former signal failure left a zombie with zero CPU and shell exit 1.
Later startup briefly looked stuck at Brushes while traced: its trace contains

on to the main UI and becomes idle. Neither observation explains all other

## Remaining limits

- GIMP's preference backup calls `rename` (IRIX syscall 1114), which remains
  unimplemented. First-run output reports failure to rename `gimprc` to
  `gimprc.old`; preference persistence is not qualified.
- `shmget` is unavailable. GDK and GIMP disable shared-memory transport;
  the tested drawing and PNG plug-in path work through the fallback.
- The inventory includes 161 ELF plug-ins/modules; basic XCF/PNG operations
  and Script-Fu startup do not qualify every filter, format, scanner or
  external helper. The original xmorph/xsane links are retained as resources.
- Large images, tile swapping, overwrite/recovery behavior, printing,
  extended sessions and physical hardware remain unqualified.

The legitimate public [GIMP 1.2.5 source archive](https://download.gimp.org/gimp/v1.2/v1.2.5/gimp-1.2.5.tar.bz2)
(SHA-256 `8c94835819203d7bc9bac2266a78bb7610a6dc473043b5362dc2a2aea720773b`)
explains `sigfillset`, the setup script and small brush reads. A checked native
ptrace diagnostic confirms the original binary's actual first action:
signal 1, flags 0, handler `0x0c050210`, mask
`ffbffeff ffff3fff 00000000 00000000`. It uses temporary process breakpoints,
then kills/reaps its diagnostic tracee; imported files are never patched.

A separate trace confirms `popen`'s failed `/emul/irix/sbin/sh` and `/sbin/sh`
lookups followed by child exit 127. Its raw SHA-256 is
`eaf0d8b1e7c3095c0edf6a48205328cb1d98acdd186a0d8627910857ad8377d1`.
The native o32 `kdump` crashes on these LP64 structured records, so analysis
uses the existing host `irix-lp64-ktrace.py` reader. Vendor bytes, raw traces
and disposable disks remain in ignored `.work`.
