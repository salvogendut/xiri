# Native xdm integration

Native xdm integration passes the bounded login/session qualification on
accelerated Newport. Normal `xiritest` login starts original 4Dwm; a separate
`netbsdtest` account reaches NetBSD's standard ctwm desktop. Both use the
1280×1024 X screen. The selected manual CHD remains the qualified module
image; it has not been replaced by this userspace cycle.

Evidence: [result JSON](2026-11-03-xiri-xdm.json),
[native greeter PNG](images/2026-11-03-xdm-greeter.png),
[IRIX desktop PNG](images/2026-11-03-xdm-irix-desktop.png),
[standard ctwm PNG](images/2026-11-03-xdm-native-ctwm.png).

## Integration

The maintained runtime adds an opt-in `--enable-xdm` installation mode,
`/etc/xiri/xdm/Xservers`, a greeter resource overlay and an example user
`.xsession`. It uses native NetBSD xdm, PAM and `/etc/X11/xdm/Xsession`.
There is no auto-login or replacement password verifier. Installation preserves
existing administrator configuration and does not change account passwords,
user session files or `/etc/ttys`. See the [setup procedure](../../runtime/README.md#native-xdm-login).

Native xdm owns Xorg and its authentication/reset lifecycle. The `.xsession`
executes the existing unprivileged `xiri-session`; boot rc.d continues to own
PTY preparation, FAM and rpcbind. Local `DISPLAY=:0` becomes `127.0.0.1:0`
for the current TCP-only IRIX socket personality, while the native account's
HOME, groups and X authority remain intact. No extra cookie or access-control
exception is introduced.

The server command explicitly selects `/usr/local/share/xiri/xorg.conf`,
with 1280×1024 mode/virtual geometry and XAA acceleration. This avoids the
smaller screen the user encountered with bare `startx`. The emulator's pinned
scanout includes two additional columns (1282×1024 PNGs), as in the previous
qualified desktop captures; the active X root is 1280×1024.

## Findings from the exploratory guest

`.work/irix-xdm/runs/ordinary-7i68x3gv` initially stopped on a harness process
check: NetBSD reports xdm's absolute Xorg argv[0] as its process name, so
`pgrep -x Xorg` missed the live server. The revised probe checks the display
lock PID and actual server arguments. Its original failed result is retained;
the debug continuation does not turn that record into a qualification pass.

Real keyboard entry showed that a wrong password is rejected by native PAM.
A valid login initially returned to the greeter because original 4Dwm could
not open the Unix-domain `:0` connection. The loopback spelling resolves
this while using xdm's existing authority file. The desktop then started as
xiritest and its supervisor cleaned its descendants on a logout request.

The full replay also exposed a diagnostic assumption: xdm can supply
`XAUTHORITY=/tmp/.Xauth*`, rather than use `$HOME/.Xauthority`.
The production session already preserved this value. The corrected probe
reads the session's recorded authority pathname and uses the same loopback
display spelling; an unauthenticated client must still be rejected. Later
qualified logins used the default home authority file. Diagnostics support
both native choices.

The native greeter exposed missing Xft glyphs: its frame/logo painted, but
labels and typed text did not. Font matching finds the installed Luxi Sans
font. Disabling antialiasing alone did not help; `Xft.render: false` restored
the greeting and prompts. The resource overlay includes the stock NetBSD
resources then applies this workaround. XAA and the Render extension remain
enabled. The [Xft API documentation](https://xorg.freedesktop.org/archive/X11R7.5/doc/man/man3/Xft.3.html)
describes text drawing paths that can operate without the Render extension.
The underlying native glyph defect still needs a focused server/emulator
comparison; it is tracked in [Newport work](../NEWPORT.md).

The probe captures ordinary GL scanout and verifies visible greeter text
as well as X geometry. Captures taken before Xorg has recreated its greeter
after a restart are blank; the probe waits for the actual xlogin window.
The exploratory guest halted cleanly and preserved its source disk.

## Qualification procedure

```sh
python3 scripts/probe-xiri-xdm.py
python3 -m unittest discover -s tests -v
```

The probe clones the verified module raw seed, stages a frozen runtime,
compiles native helpers, configures the disposable account and reboots.
It explicitly selects `.xsession`, disables the competing ttyE0 getty while
retaining serial administration, and assigns the public lab password
`xiritest`. A separate `netbsdtest` account (UID/GID 1236, home
`/home/netbsdtest`, public fixture password `netbsdtest`) has no `.xsession`:
the unchanged native Xsession must start ctwm. These credentials are fixtures;
the installer never sets them.

Acceptance covers boot-started xdm/services/module, visible greeter text,
wrong-password rejection, native identity/groups/HOME/cwd, X authorization,
full-screen dimensions, the 8,536-pixel Render control, both logout menus,
return to the greeter, failed session recovery, and a further successful
login. The separate native account must reach ctwm, execute terminal commands
under its own identity/home, return to xdm after its shell terminates its own
window manager, and leave the later xiritest login working. This native logout
control ends ctwm from its terminal; it does not qualify ctwm's Quit menu.
System-service PIDs and an independent same-user shell must survive.
A pass additionally requires clean halt and an unchanged source disk.

Kernel/module and emulator artifacts are inherited from the qualified module
image (NetBSD source-equivalent `d1ce7a96615`, IRIS `819c682`). No kernel,
emulator or imported IRIX payload changes are made. IRIS upstream was fetched
at `28fa516684c54e00e35b258c65e5dcac3a36165c`, already in integration
`1aed0df`; see [fork tracking](../FORKS.md).

The final record comes from

The `qualification-v2` continuation passed both IRIX menu routes, failed
startup recovery and native ctwm login. Its keyboard helper reported an X
disconnect when the typed native WM termination immediately reset the server.
The final continuation lets the helper disconnect first, using a two-second
delay in that typed command, and rechecks native login/logout plus the final
IRIX login. Earlier passed phases are carried forward with their record hash;
reused helper bodies are checked against the current probe's AST. All runtime
implementation bytes match the staged source; only its README changed during
qualification. Source, installed-file, screenshot and parent-result hashes
are recorded in the JSON. This is a qualification across live continuations,
not a claim that the final fresh-run harness completed uninterrupted.

An earlier `ordinary-khf5057l` run was interrupted by host SIGTERM. Its guest
was recovered and cleanly halted; it is not counted as a qualification pass.
All failed/interrupted records remain under `.work/irix-xdm/runs/`.

## Remaining boundaries

FAM still serves one configured account, xiritest. Native xdm authentication
does not turn it into an authenticated multiuser FAM implementation. Original
IRIX clogin, full saved-session restoration and broader application support
remain later work. Winterm's intermittent startup/font-metric issue remains;
the probe resizes the terminal before checking typed shell commands.
The final IRIX PNG still shows compressed winterm text despite successful
command execution; this cycle does not qualify terminal font rendering.
A new CHD needs its own packaging and direct-disk-boot qualification before
replacing the existing manual image.
